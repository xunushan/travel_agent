# 问题设计

设计本次调研的问题清单时读一次。**问题清单是本 skill 的产出，不是输入**——
标准配置只是骨架，必须根据用户已给的信息重新设计。

## 拆题原则

- 标准配置 **3 个问题**（是什么 / 怎么样 / 要多久）——这是**骨架不是定稿**；
- **"路线对比""景点卖点"不单独设题**——笔记拿回来后在第 4 步汇总环节内部完成；
- **口碑、避雷不进本阶段**——那是阶段 1 的事；
- 一次一题；某题搜出来太杂，就**拆得更小**（如按路线逐条查），而不是把问题改宽。

### 动态设计的四个杠杆

| 杠杆 | 怎么调 | 例子 |
|---|---|---|
| **题量** | 意图里已明确的维度**不重复设题** | 用户说"只有 3 天"→ Q3 不单列，改为在 Q1 的要求里加"3 天以内短线"的侧重；主题已是具体路线（如"格聂南线"）→ Q1 收缩为"这条线的节点与天数"一题 |
| **措辞** | 把**主题语义写进问题**，不泛泛问 | 主题是"秋色"→ Q2 问"秋色进度与峰值期"，而不是"景色怎么样" |
| **侧重** | 显著偏好**不改问题、改要求里的判定口径** | "带狗"→ Q1 的判定口径加"带宠物信息的笔记优先"；**不新增"宠物题"**（细节归阶段 1） |
| **增题** | **命中触发条件才加**，默认不加 | 见下节 |

## 标准问题清单

以"10 月中旬去甘南"为示例，【目的地】【出行时间】是占位符。
**每个问题 = 一次 xhs-search 调用，只传两样：问题、要求**（要求＝输出结构＋判定口径；
搜索词与筛选条件由 xhs-search 自己决定，不写进要求）。

| # | 问题 | 要求（输出结构＋判定口径） |
|---|---|---|
| Q1 | 【目的地】有哪些常见的环线/路线方案？各包含哪些推荐景点、节点顺序和大致天数？ | **输出结构**：路线列表——名称 / 节点顺序 / 天数 / 一句话特点；＋景点清单（标注所属路线）。**判定**：正文要有路线结构信息（节点顺序、天数、里程至少其一）；只有风景照、无路线信息的 drop |
| Q2 | 【出行时间】去【目的地】，景色、天气、路况怎么样？（含**近期天气实况**） | **输出结构**：当季看点与进度 / 气温穿衣 / 路况概况 / 近期天气实况，**逐项标注信息年份与日期**。**判定**：要有对应该时间段的描述；年份不明的 drop |
| Q3 | 走完【目的地】的这些路线一般需要多少时间？ | **输出结构**：各路线的建议天数 / 日均车程 / 节奏快慢。**判定**：要有明确的时间/天数表述；泛泛而谈的 drop |

**带着输出意识提**：Q1 → 总览的"路线方案 ＋ 景点集合"，Q2 → "当季情况"，Q3 → "时间预算"。

## 可选增题（默认不加，命中触发条件才加）

| 候选问题 | 触发条件 |
|---|---|
| 从哪里进出【目的地】最方便？大交通/必经枢纽？ | 目的地偏远、入口多样（新疆、西藏等） |
| 【目的地】的海拔与高反概况？ | 高原主题（川西、甘南、西藏等）——**只问概况**，细节归阶段 1 风险组 |
| 【A地】→【B地】的衔接段怎么走？走哪条路、路况、大致耗时？ | 行程**跨区域**、需要在两地之间串线时（如"甘南 → 阿坝"）。<br><sub>来源：《阶段0-实测流程复盘》§五.4——上一轮实测里衔接段是"撞上的、不是搜出来的"，列为建议落文条文</sub> |

**增题不是把问题问宽**：Q1 覆盖的是目的地内部的环线，衔接段问的是**两地之间**的那一段路，
两者不重叠。行程是单目的地闭环时，没有衔接段可问。

## 给 xhs-search 的输入长什么样

一题一次调用，只有两样：

- **问题**：上面表里那一整句，占位符替换成用户的实际目的地与时间；
- **要求**：上面表里的"输出结构＋判定口径"，按本次侧重调整过的那一版。

**不传**：搜索词、搜索条件（排序/时间筛选）、top-k、读几篇——这些由 xhs-search 自己决定。
**不传**：跨题汇总的意图（"顺便和上一题的路线对齐"）——那是第 4 步的事。

用户有显著偏好时，偏好**只落在要求里**（判定口径），不另开问题、不写成约束清单。
