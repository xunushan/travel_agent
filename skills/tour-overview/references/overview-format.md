# 输出契约

组装总览、落盘、给用户反馈时读一次。`ROOT` = 数据根，默认 `~/Documents/travel_agent`
（**必须与 xhs-search 用同一个根**——各题结论文档与素材都在它下面）。

## 落盘位置

```text
<ROOT>/overviews/<trip_id>/
├── 总览.md              # 《游览总览》本体
├── assets/              # 总览里引用的内联图（ASCII 文件名副本）
└── stage1-tasks.md      # 用户圈选完成后才有：阶段 1 任务清单
```

`trip_id` = 目的地 slug ＋ 出行年月，如 `gannan-2026-10`、`chuanxi-2026-11`。
**同一个行程的反馈循环复用同一个 `trip_id`**（补充/纠偏只更新 `总览.md`，不新开目录）；
**换目的地＝新行程，另开一个 `trip_id`**。

各题的中间产物不在这个目录里——它们在 `answers/<question_id>.md` 与 `notes/`（xhs-search 的产物）。

## 内容结构（自上而下五个板块）

1. **主题与一句话结论**——如"10 月中旬甘南秋色正盛，推荐 4-5 天小环线"。
   一句话要说清"什么季节、什么看点、推荐怎么走"。
2. **当季情况**——景色看点 / 天气（含近期实况）/ 路况概况。
   来自 Q2，**逐项标注信息年份与日期**（"2025 年 10 月中旬"而不是"现在"）。
3. **常见路线方案**——每条路线给：名称 / 节点顺序 / 大致天数 / 一句话特点。
   来自 Q1＋Q3，对比在第 4 步汇总时内部完成。优先收录笔记里**现成的高清线路图**（注明来源）；
   没有合适的才用文字结构图。
4. **候选景点集合**——**按路线分组**，每景点给：名称 / 一句话定位 / **2-3 张美照**。
5. **笔记来源清单**——标题 ＋ 链接 ＋ noteId，便于溯源与复用素材。

## 格式要求（当前：Markdown）

- **单文件** `总览.md`，板块顺序固定，不自创板块、不调顺序；
- 图**一律用能渲染的内联图**：`![图注](assets/fig1-xxx.webp)`，图下跟一行说明"它有什么用"，
  再跟一行 `<sub>原图：`notes/…`</sub>` 留出处；
- **图必须复制成 ASCII 文件名副本**：从各题结论文档的 `answers/assets/<question_id>/` 复制到
  `overviews/<trip_id>/assets/`，命名 `fig<N>-<kebab-slug>.<原扩展名>`。
  **禁止引用 `notes/` 原路径**——那里含中文/emoji，百分号编码在多数 md 预览里不解码，整张图会裂开；
- **配图不另搜**：只从结论文档的关键素材里取。**某板块料不足 → 补调 xhs-search，不硬凑**；
- **收尾前逐条验**：解析 `总览.md` 里所有图片链接（相对 `overviews/<trip_id>/` 解析），
  确认文件存在，别写完就算完；
- 一张素材都指不出时**如实说没有**，不用纯文字或占位框充数。

## 阶段 1 任务清单（圈选完成后产出）

`stage1-tasks.md`：逐景点一行——景点名 / 所属路线 / 用户标记（待调研）；
用户**排除**的景点不列进来（或单列一段"已排除"便于回溯）。
这张清单就是阶段 1 的输入。
