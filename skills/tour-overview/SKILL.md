# 调研目的地并生成游览总览

## 技能介绍

围绕用户的出行意向，建立目的地全局认知并整理候选景点与常见路线方案，帮助用户了解有哪些看点、整体线路如何走、大致需要多久、当季是否值得去，以及天气与路况风险。

根据用户意向生成调研大纲，按主题调研并汇总，输出《游览总览》，供用户后续选择景点。调研侧重区域与整体线路认知。

## 步骤

```text
1. 生成调研大纲（根据意图设计问题，无法设计时询问用户）
2. 按大纲主题调研
3. 汇总判断
4. 判断缺口及是否补缺口
   需要补充 → 回步骤 2，返回后重新汇总判断
5. 输出游览总览
```

### 1. 生成调研大纲

主 agent 按 [research-outline.md](references/research-outline.md)，先明确用户需要了解的地域范围与线路关系，再设计参考路线与景点问题；当季景色、天气、路况和人流按需要补充或合并。只有无法形成有意义的问题时才询问用户。

用户给出的起终点、往返或衔接关系、大致天数等条件写入相关问题，用于寻找接近的参考线路并比较差异。每个主题列明问题、期望获取的信息和成功标准，开始调研前向用户展示。

### 2. 按照调研大纲主题调研

每次唤起一个子 agent，使用 `xhs-search` 处理一个主题，传入问题与要求；要求包含期望信息与成功标准。返回结论文档、关键素材及必要的缺口说明。

- 每个主题返回后检查其结果是否同时回答了后续主题，已回答的内容不重复调研。
- 下载、笔记、主题报告与总览使用同一文件保存目录 `$ROOT`，不设默认值。

### 3. 汇总判断

主 agent 综合各主题结论，形成目的地整体认知与候选清单：

- 整理主要区域、看点与候选景点，去重；不同名称能确认指向同一地点时合并，不能确认时保留原名。
- 比较常见路线的节点顺序、覆盖区域、大致天数与节奏；结合用户已有条件说明适用性与差异。
- 综合当季整体景色、天气与路况，说明值得前往的看点及影响游览的风险。
- 来源冲突时并列说明，识别尚未解决的内容。

### 4. 判断缺口及是否补缺口

先检查各主题已有结论能否补齐缺口，再决定是否重新调研。

- 影响目的地全局认知、路线比较或候选选择的缺口：设计更具体的补充主题，明确期望信息和成功标准，回步骤 2 调研。
- 不影响本阶段判断的内容：必要时简要说明；单景点细节留到后续阶段。
- 补充调研仍未解决的事项：保留未知内容、未解决原因及对判断的影响，不因同一缺口反复发起相同调研。

### 5. 输出游览总览

按 [overview-format.md](references/overview-format.md) 输出 `<ROOT>/overviews/<trip_id>/总览.md`。

- 按参考路线、当季景色概况与候选景点、天气与路况及人流三个板块组织内容，并保留必要的缺口说明。
- 路线图仅从主题报告的关键素材选择，按信息覆盖与方案差异去重，保留有代表性的图；没有合适图片时用节点顺序与文字说明。已有笔记或视频明确提及某景点景色时，可为该景点选择 1–2 张有代表性且不重复的风景照；没有可用素材时省略，不额外搜索。
- 风景照先复用主题报告素材；不足时按 `digest/image.md` 附录选择，描述不够明确才查看已有低清拼图。视频按 `digest/video.md` 的风景画面附录选择，不重新精读图片、抽帧或重跑视频。
- 输出为 Markdown，路线图与风景照在正文直接展示，不生成 HTML 或海报。
- 结论注明来源，时效性信息标明年份与日期；关键缺口单独说明，不用推测补齐。
- 选中素材复制到总览的 `assets/`，文件名只使用英文字母、数字和连字符，如 `fig1-route-map.webp`，在正文中直接展示图片；输出前检查图片文件与链接。

## 纪律

- 大纲和汇总判断由主 agent 完成；主题调研使用子 agent 调用 `xhs-search`。
- 调研充分后停止，不为增加来源或补齐配图继续搜索。
- **禁止确定具体路线或编排逐日行程**：仅提供接近用户意向的参考线路及候选景点，说明适用性与差异，不替用户选定一条路线。
- 不开展逐景点玩法、口碑或避雷调研，不将历史信息写成当前实况。
