# 游览路线总览（阶段 0）

围绕用户的出行意图，给出**候选景点列表与常见路线方案**，附**当季情况**（含近期天气实况）与
**时间预算**——让用户有足够信息决定"去哪些景点、走哪条线"。用户看完圈选出的景点，
就是**阶段 1 的输入**。

**做**：澄清意图 → 设计问题清单 → 逐题调 xhs-search → 汇总 → 组装《游览总览》→ 反馈循环至圈选定稿。

**不做**：

- 单景点的口碑、避雷、玩法细节——**阶段 1**；
- 实时路况/人流/天气的临行校准——**阶段 3/5**（本阶段只回答"这个季节通常怎么样 ＋ 近期实况"）；
- 搜索、下载、单篇笔记理解——**xhs-search 的职责**。

## 依赖与前置

- **`xhs-search` 是已知 skill，直接调用，不经路由**：只传两样——**问题**与**要求**
  （要求＝输出结构＋判定口径）。搜索词、筛选条件、top-k、读几篇**由它自己决定，不要干预**。
  它回**结论文档**（含关键素材路径）＋**缺口声明**（如有）。
- `chrome-agent`（已登录小红书的前台标签页）由 xhs-search 侧使用，本 skill 不管。
- 数据根默认 `~/Documents/travel_agent`，**必须与 xhs-search 用同一个根**。

## 主流程

1. **澄清**（按需，不为问而问）：缺什么问什么——主题范围 / 出行时间 / 时间预算 / 显著偏好。
2. **设计本次调研问题清单**（规则见 [references/question-design.md](references/question-design.md)）：
   默认 3 题，**按用户已给的信息动态增减**，不是照抄模板。
3. **逐题调 xhs-search**，一题一次调用，只传问题＋要求。拿回结论文档＋缺口声明。
4. **汇总**——本 skill 的核心重判断，**主 agent 直接做，不派子 agent**（各题结论文档都是短文本）：
   - 交叉印证各题结论；
   - **合并去重景点**，跨题的同点异称在此归并；
   - 内部完成**路线对比**与**景点卖点提炼**（一句话定位）——这两件事不单独设题；
   - 分歧**如实并列**，不擅自调和；
   - 发现明显缺口 → **补一个拆小的新问题**回第 3 步。
5. **组装输出内容**：按 [references/overview-format.md](references/overview-format.md) 的内容结构
   整理各板块数据与素材路径。配图**全部来自各题结论文档的关键素材，不另搜**；
   板块料不足 → 补调 xhs-search，**不硬凑**。
6. **落盘《游览总览》**（位置与格式见 references/overview-format.md），
   收尾前**逐条验图片链接能解析**。
7. **请用户反馈**（规则见下）。圈选完成 → 输出**阶段 1 任务清单**（位置见 references/overview-format.md）。

## 与用户的交互

### 开始前：澄清式提问（按需，非固定表单）

**意图已明确就直接开干**（如"10 月中旬去甘南"），不为问而问。只在缺下面这些关键项时问：

| 缺什么 | 为什么问 |
|---|---|
| 主题范围模糊 | "想去川西" → 秋色？雪山？人文？——决定问题的**措辞**与判定口径 |
| 出行时间 | 决定"当季情况"怎么问、结论标注哪个年份 |
| 时间预算 | 决定路线方案的取舍——3 天小环线还是 7 天大环线 |
| 显著偏好 | "带狗""想露营"——**改判定标准，不展开约束**，也不据此新增问题 |

### 产出后：反馈处理（必需）

| 反馈类型 | 处理流程 |
|---|---|
| **圈选**（正常路径） | 记录每个景点的 待调研/排除 标记 → 输出阶段 1 任务清单 |
| **补充/纠偏**（"想看看 XX 方向""路线天数不对"） | 拆出新问题 → 再调 xhs-search → 更新总览对应章节 → **再次请用户确认** |
| **方向调整**（"其实更想看雪山"） | 回到第 1 步澄清新方向，按需增补/替换问题后继续；已下载的笔记留在素材库可复用 |

**换目的地不是反馈**（"改去新疆"）——那是规划新行程，另走一遍完整流程。

## 硬性不变量

1. **不干预 xhs-search 的内部实现**：只传 问题＋要求。搜索词、筛选条件、读几篇不传、不问、不指定。
2. **一次调用一题**。某题搜出来太杂，就**拆得更小**（如按路线逐条查）再调，不把多问并成一次调用。
3. **汇总是本 skill 自己的判断**，不派子 agent；跨题的取舍、去重、路线对比**只发生在第 4 步**。
4. **配图不另搜**，只从各题结论文档的关键素材里取。**任何板块料不足，先补调 xhs-search**，
   不允许把缺料交给下游硬凑。
5. **分歧如实并列**，不调和、不取平均、不擅自选一个。
6. **涉时效的结论标注信息年份**（价格、班次、花期、开放时间、路况、天气）——
   用去年（甚至更早）的情况回答今年的行程是错的。
7. **每个结论可溯源**到 `notes/` 里的具体笔记；来源清单不落，就不算达到完成标准。
8. **图必须是能渲染出来的内联图**：总览里引用的图要复制成 **ASCII 文件名**副本，
   不引含中文/emoji 的原路径（细则见 references/overview-format.md）。
9. **HTML 与海报由独立的生成方出**，本 skill 只负责给它**内容**（§5.1 的内容结构）与
   **要求与标准**（references/overview-format.md 的生成要求）；生成执行**派子 agent**，
   原始 HTML 不进主上下文。**当前该生成方未就位，本 skill 先直接产出 Markdown 总览**。
