# 小红书搜索问答

## 技能介绍

接受一个问题及回答要求，自行设计搜索词与条件，筛选候选、逐篇理解并汇总，输出结论文档及必要的缺口说明。

| 输入 | 说明 |
|---|---|
| 问题 | 本次搜索与回答的主题，一次一题 |
| 要求 | 需要回答的内容、输出结构及判断充分性的口径；可包含读取数量限制 |

输出：`answers/<question_id>.md`，包含结论、关键素材及必要的缺口说明。

## 步骤

```text
问题＋要求
  ↓
1. 构造搜索词、条件与 top-k（主 agent）
  ↓
2. discover＋下载 note/cover（子 agent）
  ↓
3. 粗筛，返回有序待读列表（子 agent）
  ↓
4. 下载完整内容并理解一篇（子 agent）
  ↓
5. 对照要求判断（主 agent）
  ├─ 充分回答或达到停止条件 → 6. 汇总输出
  ├─ 仍有待读项 → 回步骤 4
  └─ 无可用候选或队列读完仍有缺口 → 回步骤 1
```

### 1. 构造搜索词与条件

主 agent 按 [query-design.md](references/query-design.md) 确定本轮搜索词、条件和 top-k。

- 首轮依据问题，后续针对未回答的内容，不重复搜索已充分回答的方面。
- 每轮一个词组，top-k 最多 6。
- 将搜索词、条件、top-k 及搜索目的写入本轮日志；首轮按下方记录要求创建。

### 2. 发现候选与轻量下载

唤起子 agent，使用 `xhs-downloader` 搜索并下载候选的正文与封面。

- 指定搜索词、筛选条件、`--limit`（top-k）、`--part note,cover` 和 `--data-root`（文件保存目录，不设默认值）。
- 返回候选 noteId、笔记目录及下载结果，主 agent 写入本轮日志。

### 3. 粗筛

唤起子 agent，按 [screening.md](references/screening.md) 判断哪些候选能提供问题所需信息，返回筛选结果与阅读顺序。

主 agent 提供该文档要求的输入，其中已读清单从本次日志的 `reads[].id` 提取；返回结果写入本轮日志。

### 4. 逐篇理解

按粗筛顺序，每次唤起一个子 agent，先使用 `xhs-downloader` 补齐该篇所需图片或视频、评论，再使用 `xhs-digest` 理解并返回报告；指定笔记目录、问题与要求。

- 如该篇笔记已有存档，则直接复用，按当前问题生成报告。
- 每篇报告返回后先执行步骤 5，再决定是否读下一篇。

### 5. 判断继续、换词或停止

主 agent 对照要求检查已有结论，判断是否已经基本回答问题：

- 已基本回答或达到纪律中的上限：停止，进入步骤 6。
- 仍需信息且有待读笔记：回步骤 4。
- 无可用候选或队列读完仍有缺口：回步骤 1 换词。

每篇理解后更新已读清单、新增信息与剩余缺口，按下方记录要求保存。

### 6. 汇总与输出

主 agent 汇总已读报告，按下方要求和 [output-formats.md](references/output-formats.md) 生成结论文档。

基于已精读笔记，对可能指向同一地点的不同名称进行对齐：能确认的合并并标注其他名称与来源；无法确认的保留原名，将待确认的名称关系及依据放入缺口。不为核实名称另行搜索。

## 输出要求

### 结论

- 结构按回答要求组织，直接写结论本身，层次清晰、表述简明，不写覆盖清单。
- 每项标来源 noteId，多篇支持时列出相关来源；保留原信息的地点、时段、数值及适用条件，例如某一路段的海拔不能写成全线海拔，冬季运行规则不能写成全年规则。
- 来源冲突时并列说明，不擅自选取或取平均；未解决的分歧列为缺口。
- 价格、班次、观赏窗口等时效性信息注明所属年份，不直接当作当前状态。

### 素材选择与保留

- 只保留与问题直接相关、清晰且用途明确的素材。同类或重复内容择优保留，在满足要求的前提下最小化数量。
- 配图先根据 `image.md` 的全部图片附录选择，描述不足时再看已有低清拼图；视频信息帧按 `video.md` 中关键帧说明选择，景点照按“附录：风景画面”选择；旧存档无附录时复用其他现有素材。不重新精读原图或视频，不为补图重跑管线。
- 以内联图加图注展示，每张说明用途与来源，不重复全部提炼内容；没有可用素材时写简短说明。
- 将选中的图片复制到 `answers/assets/<question_id>/` 供答案引用，使用只含英文字母、数字和连字符的文件名，如 `fig1-route-map.webp`；原图片不移动、不改名。
- 图片侧置或倒置时，只将复制后的图片转正，并在图注中说明。最终检查所有图片链接和文件。

### 缺口

- 记录停止时仍影响回答的未确认事项，写清尝试、未解决原因及证据；无法确认的名称关系同时保留判断依据。
- 将采集、读取失败与内容未提供区分，不把故障或有限检索解释为“小红书没有这项信息”。
- 缺口放在结论文档末尾，并同步记录到 run 日志。

## 记录

主 agent 按 [run-log.md](references/run-log.md) 维护本次日志：

- 首轮创建记录，`reads` 已读清单为空。
- 每轮保存搜索配置、候选、下载与粗筛结果。
- 每篇报告返回后立即将 noteId、信息贡献、覆盖情况和剩余缺口写入 `reads`；每个 noteId 只记录一次。失败项写入 `failures`，不算已读。
- 停止时记录原因、未读候选、引用来源与缺口；中途叫停也保存当前进度。

## 纪律

- **读够即停**：已有笔记已基本回答问题时立即停止，不为增加来源继续阅读。
- **数量上限**：搜索不超过 6 轮，单题阅读不超过 20 篇；这是上限，不是目标数量。
- **逐篇判断**：不批量或并行派出完整理解任务；上一篇判断完成后才派下一篇。
- **存档复用**：已有 digest 存档的笔记不重复下载或理解，直接按当前问题生成报告。
- **本轮任务去重**：同一个问题下，已返回报告的笔记不再次派单；主 agent 用日志的 `reads[].id` 记录这些笔记，换搜索词后继续使用。
- **统一保存目录**：下载、笔记、答案与日志使用同一文件保存目录 `$ROOT`。

## 保存路径

```text
<ROOT>/answers/<question_id>.md          # 结论、关键素材与必要缺口
<ROOT>/answers/assets/<question_id>/     # 答案引用的图片
<ROOT>/runs/<question_id>.json           # 过程日志与本次已读清单
<ROOT>/notes/<noteId>_<标题>/             # 下载内容与 digest 存档
```
