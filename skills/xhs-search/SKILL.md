# 小红书搜索问答

给**一个问题**和**一份要求**，在小红书上跑完整闭环，产出**结论文档**（有未覆盖项时再出一份
**缺口声明**）。

**不做**：拆问题、跨问题汇总、与用户交互（调用方的事）；搜索下载（xhs-downloader）、
单篇理解（xhs-digest）。

**输入**（仅两样）：

| 输入 | 说明 |
|---|---|
| 问题 | 判断与回答的单位，一次一题 |
| 要求 | 答案要覆盖的维度/结构（如"路线列表：名称/节点顺序/天数/特点"），可含"怎么算能回答"的判定口径 |

搜索词、搜索条件（排序/时间筛选）、top-k、读几篇——**全部由本 skill 自己决定**，不是输入。

输出只有两样——**结论文档**，和**缺口声明**（仅当多轮尝试后仍有未覆盖项时存在）。
digest 存档、run 日志都是中间数据，**不是输出**。

## 依赖与前置

- `xhs-downloader`（discover＋download）、`xhs-digest`（单篇理解）是**已知 skill，直接调用，
  不经路由**；它们的 SKILL.md 就是接口。
- 两者都靠 `chrome-agent`，需要一个**已登录小红书的标签页**（采评论必须前台）。
- 数据根默认 `~/Documents/travel_agent`：索引 `xhs.db`、笔记 `notes/`，本 skill 的
  `runs/` 与 `answers/` 也在同一个根下（结构见 [references/output-formats.md](references/output-formats.md)）。

## 按需加载

| 需要什么 | 读哪份 |
|---|---|
| 构造搜索词与搜索条件（每轮开头读一次） | [references/query-design.md](references/query-design.md) |
| 派粗筛子 agent——**随任务书下发，主 agent 自己不用读** | [references/screening.md](references/screening.md) |
| 写结论文档、缺口声明、run 日志（收尾读一次） | [references/output-formats.md](references/output-formats.md) |

换词与停机**不拆文件**——就三条触发＋三行表，主 agent 每次打勾都要对照，写在下面。

## 主循环

每轮五步：

1. **构造搜索词＋搜索条件＋top-k**（规则见 [references/query-design.md](references/query-design.md)）。
2. **派子 agent 执行 discover＋download**：调 `xhs-downloader` 搜这一个词、施加条件、
   下载 top-k 篇的 `note,cover` 两个内容件，**回主 agent 的只有候选清单**（标题＋摘要＋
   互动数＋publishedAt＋类型），原始页面内容不进主上下文。
3. **派子 agent 粗筛**：把问题＋要求＋候选清单＋**已读 noteId 清单**（＝主 agent 自己记的
   `reads`）交给它，契约随任务书下发（[references/screening.md](references/screening.md)），
   拿回 keep JSON（有序）。
4. **按 keep 顺序逐篇派子 agent**：`xhs-downloader` 下载该篇完整内容件 → `xhs-digest`
   理解（带问题与要求），拿回报告。**一篇一个子 agent，逐篇来。**
   **已读过的不再读**——粗筛漏掉的，这里跳过。
5. **对照"要求"逐项打勾**（主 agent），三选一：
   - 全覆盖 → 走收敛；
   - 本轮 keep 还有没读的 → 回第 4 步读下一篇；
   - keep 读完仍有缺项 → 换词，回第 1 步。

**收敛**：写结论文档＋缺口声明（如有），落 run 日志，结束。**同点异称在这一步归并**，
判不准的进缺口声明（见不变量 10）。

**换词触发**（满足任一）：粗筛 keep 为空；连续 ~3 篇读完无增量；本轮 keep 读完仍有缺项。

**停机准则**（满足任一即停）：

| 准则 | 阈值 | 停后动作 |
|---|---|---|
| 闭合 | 对照"要求"逐项有带来源的结论支撑 | 输出结论文档，剩余候选不再读 |
| 轮次上限 | 最多 **6 轮**搜索——有些内容小红书上就是没有答案 | 未覆盖项写进缺口声明，照常输出 |
| 深度上限 | 单题完整理解 **~10 篇**软上限、**20 篇**硬停 | 同上 |

## 硬性不变量

1. **主 agent 只做决策**：构造搜索词与条件、对照要求打勾、换词、停机、写输出。
   一切执行（搜索下载、粗筛、逐篇下载＋理解）**全部派子 agent**；回主 agent 的只是各步的
   简洁结论（候选清单、keep JSON、报告）。**长文与原始页面不进主上下文。**
2. **一次一词**：一轮搜索只用一个关键词，多词合并会丢候选。
3. **粗筛从宽**：只 drop 明显无关、广告、地区不符；拿不准一律 keep 并压低优先级
   （**误杀代价远大于白下载**）。
4. **结论逐项对齐要求**：每项写全结论本体、标来源 noteId；**分歧如实并列，不擅自调和**；
   涉时效的结论**标注信息年份**。缺项不糊弄成"大致如此"——够不上覆盖就写进缺口声明。
5. **缺口是例外不是常态**：按"要求"尽力答完；缺口只收录**多轮尝试（直至停机）后仍无法获取**
   的项，附试过的搜索词与判断无法获取的理由。
6. **不把"没读到"当"没有"**：下载/理解失败是运行故障，不是笔记的性质。故障要重试或如实
   标注，**绝不允许据此宣称"小红书上没有这个信息"**。
7. **报告只对当前一篇负责**：xhs-digest 的报告不跨笔记；跨笔记的取舍与汇总**只发生在主 agent
   打勾与写结论文档时**。
8. **一篇只读一次**：换词后候选与已读重叠是常态，所以**已读清单每轮随粗筛任务书下发**，
   已读的一律不进 keep（粗筛漏了，主 agent 在第 4 步跳过）。读懂这一侧的规矩是**档案不重做**——
   `digest/` 在 = 解析过：跳过管线，不够时按 xhs-digest 的"定向补读"增补，**既不重跑管线，
   也不对同一篇重复出报告**。
9. **素材必须能渲染**：结论文档里的图是**内联图**，不是裸路径——复制成
   `answers/assets/<question_id>/` 下的 **ASCII 文件名**副本再引（直接引 `notes/` 原路径会因
   中文/emoji 的百分号编码在预览里裂开），原图不动。细则见
   [references/output-formats.md](references/output-formats.md)。
10. **同点异称在收尾归并，且不触发搜索**：不同来源各叫各的名字时，写结论文档这一步**只按
   已读内容**归并——同点只出现一次、异称括注在正名后并标来源；**判不准的不并**，升级为
   缺口声明的一条（附疑似依据）。**别名不发起补搜、不换词、不改主链路。** 细则见
   [references/output-formats.md](references/output-formats.md)。
