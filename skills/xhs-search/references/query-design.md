# 构造搜索词与搜索条件

每轮开头读一次。构造的依据是**问题与要求**，加上**上一轮读到了什么、还缺什么**。

## 搜索词

- **组词公式：对象 ＋ 信息形态词**。小红书搜索页提供的 tag 可直接用来组词：导航定位、
  门票价格、路线图、分布图、实况、照片、最佳时间、看日出、攻略、自驾、海拔
  （如"扎尕那 分布图""扎尕那 门票价格"）；tag 也可当作"这个问题有哪些可查维度"的提示。
- **泛词低效、形态词高效**："扎尕那旅游攻略"这类词同质化严重且夹广告，**避免单用**。
- **一次一词**：一轮搜索只用一个关键词，多词合并会丢候选。
- **top-k 默认 8**：一个关键词下有效候选通常 3–5 篇，**候选少是常态，换词比深挖重要**。
- **换词的依据**：
  1. 已读笔记回答了什么／还缺什么（对照要求）；
  2. 已读笔记里长出的新词——新地名、新形态词（digest 报告的缺口和素材里常有）。

## 搜索条件建议

| 问题类型 | 排序 | 时间筛选 |
|---|---|---|
| 路线/结构类（路线方案、分布、时长） | 最多收藏 | 不限——好的路线笔记普遍发布 1–4 个月前，限时间会杀掉它们 |
| 口碑/评价类 | 最多收藏 | 不限，同题多篇时挑 `updatedAt` 近的 |
| 观赏窗口类（秋色进度、花期） | 最多收藏 | 不限，搜索词带月份（如"10月"）；若问的是"今年秋色在什么时间段"这类实时进度，改最新＋一周内 |
| 路况/人流类 | 最新 | 一周内 |
| 天气类 | 最新 | 一天内 |

以上均为**建议默认值**，可按实际情况灵活调整（如条件太严导致候选稀少就放宽）。

## 两条约束

- 时间筛选**只有四档**（不限／一天内／一周内／半年内）；判断笔记时效看 `publishedAt`／
  `updatedAt` 中**较晚者**，结论标注年份。
- **有哪些维度只能 `--list-filters` 当场读，没有词表**，词表不在这里重复；机制与实测记录见仓库
  `docs/xhs-筛选机制与实测.md`（原 `references/filters.md`，2026-10-09 移出 skill）。
  已知五个维度：排序依据（综合/最多收藏/最新/最多点赞/最多评论）、笔记类型（不限/视频/图文）、
  发布时间（不限/一天内/一周内/半年内）、搜索范围、位置距离——**以 `--list-filters` 的当场输出为准**。
