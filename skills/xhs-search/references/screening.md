# 粗筛子 agent 契约

**这份文件随粗筛子 agent 的任务书一起下发。主 agent 自己不用读。**

## 任务

一次批量判断一轮候选，决定哪些值得下载精读。

## 输入

问题 ＋ 要求 ＋ 候选清单 ＋ **已读 noteId 清单**。每条候选给：`noteId`、标题、200 字摘要、互动数、`publishedAt`、类型。

## 判法

1. **先剔已读**：`noteId` 在已读清单里的，直接 `keep: 0`、`why: "已读"`——**不重判、不看封面**。
   换词后候选与已读重叠是常态，这一步是硬过滤，排在其它判据之前。
2. **扫标题和摘要**；
3. **拿不准的再看封面**（读图约 1–1.5k token）——**能凭文本判的不看**；
4. **从宽把握**：只要主题沾边、可能含所需信息就 keep；只 drop 明显无关、广告、地区不符；
5. 拿不准一律 keep 并**压低优先级**——**误杀代价远大于白下载**；
6. `pri` 即阅读顺序：最可能直接命中要求的排前面。

## 输出（只回这一段，不回理由长文）

```json
[{"id": "noteId", "keep": 1, "pri": 1, "why": "≤10字"}]
```

- `keep`：1 留、0 丢；**输出必须覆盖输入的每一条**（已读的也照出），不许省略；
- `pri`：仅 keep 的条目需要，从 1 递增；`keep: 0` 的记 0；
- `why`：≤10 字，说清留/丢的判据。

## 固定契约

结构固定，不随执行者变——目前由主模型执行，后续换小模型时**只换执行模型，流程不动**。
