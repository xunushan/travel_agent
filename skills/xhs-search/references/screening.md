# 候选笔记粗筛

## 输入

- **问题与要求**：包括当前尚未回答的内容。
- **候选清单**：每篇的 noteId、笔记目录、`note.json` 与封面文件路径。
- **本次已读清单**：由主 agent 从 `<ROOT>/runs/<question_id>.json` 的 `reads[].id` 提取并随任务传入；没有已读项时传空列表。

主 agent 每篇拿到完整理解报告后，立即将该篇写入 run 日志的 `reads`，供后续轮次使用。此清单只记录本次问题已理解的笔记；已有 digest 不等于本次已读。

## 步骤

### 1. 排除本次已读笔记

noteId 在已读清单中时，直接记为不留、理由“已读”，不再读正文或封面。

### 2. 优先阅读 note.json

结合标题、正文与问题要求，判断能否提供所需信息。

- **相关则保留**：能提供路线、景点、节点顺序、时间等当前所需信息，简述具体贡献。
- **无关则排除**：仅出现目的地词，或主体为商品、箱包装载、个人晒图，未提供所需信息，不保留。
- **部分相关可保留**：能回答部分要求时说明适用范围，不因起终点或行程不同直接排除。
- 能判断相关或不相关时，不读取封面；不能判断时进入下一步。

### 3. 无法判断时阅读封面

只判断是否提供问题所需的信息，不做完整图片理解，不保存封面提炼结果。

- 根据可见内容判断，不推测未展示的信息。
- 不逐字抄录、裁切放大或继续读取图集与视频。
- 仍无法判断信息贡献时，不列入待读，理由“信息不足”。
- 正文或封面读取失败时记录失败，不将运行故障判为内容无关。

### 4. 排序

按回答当前缺口的能力排序：直接回答所需信息的优先，局部相关的其次。结合信息具体程度与适用地域、时段判断，互动数仅作辅助参考。

## 输出

```json
[
  {"id": "noteId", "keep": 1, "pri": 1, "why": "提供节点顺序"},
  {"id": "noteId", "keep": 0, "why": "装载记录无路线"},
  {"id": "noteId", "keep": 0, "why": "已读"},
  {"id": "noteId", "keep": null, "why": "正文读取失败"}
]
```

- 覆盖全部输入候选，不省略已读、排除或失败项。
- `keep`：1 为保留，0 为不留，null 为读取失败、尚未完成判断。
- `pri`：保留笔记的阅读顺序，1 表示最先读，随后为 2、3……；仅 `keep: 1` 的条目填写，其他条目省略。
- `why`：简述信息贡献、排除或失败原因，不返回分析长文。
