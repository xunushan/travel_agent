# 怎么判断哪几篇值得下载

摘要表一到手，对每条回答 keep 还是 drop，再回答一个整体问题：**够不够做决定**。

## 一条一条看什么

按这个顺序看，前面的够用就不必看后面的：

1. **标题 + 发布时间**：旅游信息有保质期。「XX 景区开放时间/门票/路况」只看近期的；
   「经典路线怎么走」旧一点无所谓。行里的 `卡片时间` 是站点打印的模糊时间（`4天前`/`09-27`），
   `发布时间` 是从 noteId 解出的精确日期，**两者不一致时以后者为准**；若带
   `编辑于<日期>`，说明这条被改过，通常比发布时间更可信。
2. **标签 + 正文摘要**：标签看主题是否对得上（`川西`/`秋色`/`自驾`）；摘要看有没有**具体信息**
   ——数字、时间窗、地名、票价、路况，而不是抒情。`--excerpt 150` 一般够判断；
   摘要末尾的 `…` 说明被截断了，正文全文在磁盘上。
3. **封面图**：只有前两步都判不了时才 Read 摘要里给的封面路径。小红书的封面常常就是信息本体
   （**时间表、路线图、机位清单、装备清单**），而正文里可能一个字都没提。读图花 token
   （约 1–1.5k/张），所以是**补充手段而不是默认动作**。
4. **互动数**（赞/藏/评/享）：只作弱信号。**收藏高**通常意味着「有用、值得回看」，
   这比点赞更能说明对决策有用；评论多说明有争议或有人在问答，可能要下载评论。

## 常见的 drop 理由

- 只有风景照、没有可用的时间/地点/价格信息
- 时效过了（花期/封路/活动已结束），而你要的正是时效信息
- 主题偏了（不同季节、不同线路、不同人群）
- 明显的广告/团购/带货

## 别做的事

- **不要为了「更全」多看笔记。** 目标是一轮里留下通常 **≤10 篇**；如果 20 条里够格的远少于
  预期，正确的动作是**换搜索词或换筛选再搜一轮**，不是把 `--screen-limit` 调大继续翻。
- **不要重复判断库里的结论。** 行尾带 `[已筛过:keep|drop]` 的是库里已有的判断，
  已经 drop 的不必再看；要改判就直接记一条新的。
- **不要用读正文全文来补判断。** 摘要不够就说清楚不够，去 Read 封面；两样都不够说明这条本来就
  该 drop。
- **不要读评论来判相关性。** 阶段一不读评论（那是阶段二的事），评论只影响「要不要看评论区」。

## 记判断

```bash
python "$SITE/scripts/decide.py" keep --run-id 7 --note-id <id>,<id> --reason "有时间表和机位"
python "$SITE/scripts/decide.py" drop --run-id 7 --note-id <id> --reason "只有风景照"
```

`--note-id` 是一个参数、逗号分隔（逗号周围可以有空格）。`--reason` 原样写进台账，
写给以后的自己看——写「为什么有用」，不是写「有用」。

**整体问题只有一个**：这一轮的摘要表够不够支持判断？

- 够了 → `decide.py keep` 记完，进阶段二。
- 不够，但方向对 → 换更具体的词或收紧筛选，再跑一轮（不带 `--run-id` 即新建 run）。
- 不够，方向也不对 → 换词重搜，别在旧候选里硬挑。
