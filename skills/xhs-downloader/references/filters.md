# 筛选：机制、证据、怎么挑

## 结论先行

1. **没有词表文件。** 有哪些维度、每个维度有哪些选项，一律**运行时从当前页面读**
   （`search.py filters`）。页面改版不会留下一份过期词表，没预料到的选项照样可选。
2. **只能点控件。** 拼在 URL 上的 `sort=`/`noteType=` 一律无效（实测见下）。
3. **点完必须验证生效**，验证的是页面自己的生效标记，不是结果卡片有没有变。
4. **UI 里挑不到的组合就别硬凑**：报错信息会列出真实可选项。

## 页面上有什么（实测 2026-10-07）

**常驻 channel 行**（`div.search-layout__top` 内，不需要点开任何东西）：
`全部 | 图文 | 视频 | 用户`，实测 x=267/331/395/459、y=88，当前项靠类名 `active channel` 标记。
它比弹层多一个 `用户`，所以「按笔记类型筛」优先在这一行解决，一次点击、不开弹层。

**筛选弹层**（右侧 `div.filter`，实测 x=1324 y=88 w=84）：分组为**排序依据 / 发布时间 /
搜索范围**一类的维度，每组一组 `div.tags` 选项。弹层里的 `不限` 就是 channel 行的 `全部`
（只有这一对互为别名，其他一律不做别名——别名表就是这套设计要避免的词表）。

**状态读不出选项**：SSR 状态里 `search.filters = null`、`activeFilters = []`，所以必须打开弹层
实测。旁证是 `appSettings.searchFilterGuideConfig`（`maxDailyShow/maxTotalShow/showInterval/
validDays/autoCloseDelay`）说明该功能真实存在。

## 为什么只能点，不能拼 URL

实测：导航到带 `sort=time_descending&noteType=2` 的结果页，页面自己的 `searchContext` 仍是
`general`/`0`，一张卡片都没动。站点把筛选放在客户端状态里，只有点击能设置它。

`SEARCH_URL_TEMPLATE`（`runtime.py`）里的 `source=web_search_result_notes&type=51` 是结果页自己
发的参数，**不是筛选**，改它不会改变排序或笔记类型——别在这上面做文章。

注意 chrome-agent **没有 hover**：靠 hover 才展开的弹层点不通（当前筛选弹层是靠点击展开的）。

## 怎么读、怎么点、怎么验

- `open_panel()` 先看弹层是不是已经开着；开着就不再点（再点会把已开的关掉）。
- 每个选项在快照里**出现两次**（实测 `综合` 同时是 e667 与 e669，都带 `tags active`），
  按矩形去重后再读，否则选项数会翻倍、裸选项会跟自己撞歧义。
- 分组的名字取组内的 label span，而 label 是靠**排除法**找的（组里除了 label 就只有各选项里的
  span）——「取第一个 span」今天能用，选项一旦排到 label 上面就错。
- 选项按**可见文本精确匹配**（先 `one_line` 压平空白）。
- 施加：`page click --ref <选项 ref>` → 等 `filter_settle` 秒 → 重新快照，要求
  `(维度, 选项)` 出现在 `active_options()` 里。没出现就**中止**，因为继续下去会拿到一批没筛过的
  结果，而它看起来跟一次成功搜索一模一样。
- `--filters` 一项写 `维度=选项`，维度可省；省了维度而**多个组都有这个选项时直接报错**，
  不猜。选项文本里含 `=` 也没问题（只按第一个 `=` 切）。
- 一轮里每个搜索词都重新施加一遍筛选：没有任何证据表明站点会在导航之间保住选择。

## 怎么挑（给智能体的判断要点）

- **先按意图需要的时效挑「发布时间」**：找「最近的花期/路况/开放时间」这类会变的information，
  用「一周内 / 一月内」；找「经典路线、攻略」这类慢变内容，「不限」反而更全。
- **要图集/路线图/时间表** → 笔记类型挑 `图文`；要**路况、实地视频** → `视频`。
  不筛时默认 `全部`。
- **排序按目的**：想看**最新动态**用「最新」；想让**高赞的经典攻略**排前面用「最多点赞」或
  「最多评论」；**没有明确意图就用「综合」**。
- **一轮别贪多**：默认 `--limit 10` + `--screen-limit 10`，**每个搜索词各算一份**。
  一段搜索词给出十来条就足以判断该不该换词了，人的阅读量也就在这个量级。候选太多说明词太宽，
  换词比调大 `--screen-limit` 更省时间（每多打开一篇就多一次整页加载）。
  一个词要不要换，看它小节里的「未展开 N 条」和「页面上还有更多」——那是这个词没被看全的证据。
- **筛选没生效、或某个维度页面上根本没有**时，`search.py filters` 的输出就是权威清单；
  报错信息里也会直接列出可选组与选项。
