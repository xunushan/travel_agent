# 视频笔记理解管线

## 原则

**先以低成本定位有价值的内容，最小化整帧读取次数。** 口播通过 ASR 与字幕理解，信息画面与风景画面统一按线索定位、候选拼图筛选和择优保存；仅信息画面进入精读。

## 执行步骤

以下 `$SITE` 为 skill 根目录，`$N` 为笔记目录，`$V` 为选中的视频文件，均使用绝对路径。`Read` 表示读取文件或以多模态查看图片，不是 shell 命令。

### 1. 阅读正文，确定主题与视频线索

读取标题与正文，确定主题、正文信息及视频内容的引用说明。

**输入**：`note.json` 的标题与正文、`videos/` 中的视频文件、用户问题与要求（如有）。

```text
Read $N/note.json
选择 videos/ 中本次处理的视频，设置 $V
```

- 保留主题相关的正文信息，供最后汇总使用。
- **利用问题线索**：提供问题时，结合其中的目的地、时间、路线及关注事项，在笔记主题范围内优先筛选、理解和总结相关信息。
- 记录正文对视频画面内容的引用说明，供后续定位。

**输出**：主题、正文信息与视频内容线索。

### 2. 转写音频，保存原始转写

检查 ASR 依赖，提取音频并生成带时间戳的原始转写。

**输入**：`$V`、ASR 引擎及模型。

```bash
bash "$SITE/scripts/setup-asr.sh"
mkdir -p "$N/digest/assets/frames" "$N/digest/scratch"
ffmpeg -hide_banner -loglevel error -y -i "$V" -vn -ac 1 -ar 16000 -c:a pcm_s16le \
  "$N/digest/scratch/asr.wav"
"$SITE/bin/llama-funasr-sensevoice" \
  -m "$SITE/models/sensevoice-small-q8.gguf" \
  -a "$N/digest/scratch/asr.wav" --vad "$SITE/models/fsmn-vad.gguf" \
  --srt > "$N/digest/assets/asr-raw.txt"
```

- 依赖安装说明见 [asr-setup.md](asr-setup.md)；安装失败则说明缺口并停止。
- 原始转写保留，不直接改写；后续校正另行记录。

**输出文件**：`digest/assets/asr-raw.txt`。

### 3. 查看探测帧，确定阅读方式

通过少量等距探测帧，判断视频形态、字幕位置及是否穿插信息图卡。

**输入**：`$V`、步骤 1 的主题与视频线索。

```bash
python3 -I "$SITE/scripts/probe.py" "$V" "$N/digest/scratch/probe"
python3 -I "$SITE/scripts/sheet.py" "$N/digest/scratch/probe" \
  "$N/digest/scratch" --prefix probe-contact
```

```text
Read 生成的 probe-contact-*.jpg 拼图，不逐张读取探测帧
```

| 判别内容 | 后续处理 |
|---|---|
| 口播、动画或实拍 | 判断信息主要来自口播还是画面；结合文字记录信息画面与风景片段线索，统一在步骤 5 定位与筛选 |
| 字幕与要点文字的位置、层数 | 每层分别测量裁切区域；有字幕走步骤 4，无字幕以 ASR 为基础，必要时核对相关画面 |
| 是否穿插信息图卡 | 结合正文与转写，在步骤 5 定位有价值的画面 |

- 拼图使用默认 480 px/格，不提高每格分辨率。
- 探测帧只用于判断阅读方式，不依赖等距抽帧确定图卡的具体时间。
- 多层文字分别处理。例如 720×1280 视频可能同时有下部对白字幕（y≈935–1115）及上部要点文字（y≈250–310），不能只读其中一层。

**输出**：视频形态、各层文字的裁切区域、图卡线索及有地点依据的风景画面线索。

### 4. 阅读字幕带，校正转写

将字幕带按时间间隔拼接阅读，结合 ASR 补充漏句并核对地名、数字等信息。

**输入**：`$V`、`digest/assets/asr-raw.txt`、步骤 3 确定的各层文字区域。

#### 4.1 生成并阅读字幕拼图

按步骤 3 确定的文字区域裁切并拼接，逐张阅读生成的长图。

```bash
# 示例适用于 30 fps、720×1280 视频；crop=W:H:X:Y 须按实际字幕区域调整
ffmpeg -hide_banner -loglevel error -y -i "$V" \
  -vf "select='not(mod(n,90))',crop=720:180:0:935,tile=1x12" -vsync 0 \
  "$N/digest/scratch/sheet_%02d.jpg"
```

```text
Read 生成的字幕带长图
```

- 默认每 3 秒采一帧；`mod(n,90)` 对应 30 fps，其他帧率按实际值调整。12 帧拼一张长图，覆盖约 36 秒，一次 ffmpeg 调用生成全片长图。
- 多层文字分别裁切、拼接，使用不同文件前缀，避免覆盖。

##### 采样成本参考

720×180 字幕带约 182 token/帧，整帧约 1196 token；每张字幕长图约 2k token。450 秒视频的参考量级如下：

| 间隔 | 长图数 | token |
|---|---|---|
| 5 秒 | 8 | ~16k |
| **3 秒（默认）** | 13 | ~26k |
| 2 秒 | 19 | ~39k |
| 1 秒 | 38 | ~77k |

不默认提高采样密度。450 秒视频按 1 fps 读取整帧约需 54 万 token。

#### 4.2 核对漏句与转写错误

对照字幕与 ASR，仅提取需要核对的时间点。

```bash
python3 -I "$SITE/scripts/frame_grab.py" "$V" "$N/digest/scratch" \
  --at 123 --crop 720:180:0:935
```

- 字幕单句可能只显示 1.8–2.8 秒，默认间隔会漏句；结合 ASR 时间戳提取缺失句所在的字幕带。
- 无字幕时使用 ASR 转写；地名、名单、数字或时间需要核对时，仅查看对应时间点的相关区域，不批量读整帧。无法确认的内容保留存疑。
- 地名及专有词根据字幕或已选中的有效画面校正，不按词频猜写法；每条校正注明依据。

#### 4.3 保存校正结果

生成可读全文与校正记录，保留原始转写。

**输出文档**：`digest/assets/transcript.md`、`digest/assets/asr-corrections.md`，按 [format-video.md](format-video.md) 中的对应要求编写。步骤 6 若发现新的校正依据，同步更新这两份文档。

### 5. 定位画面，通过拼图筛选候选

结合正文、口播与校正转写定位候选片段，通过低清拼图统一筛选信息帧与风景画面。

**输入**：`$V`、正文引用说明、`digest/assets/transcript.md`、探测帧线索；必要时对照原始转写。

#### 5.1 定位候选展示段

- **口播提示**：作者介绍汇总、路线规划或提示查看图表的时间点，例如“截图保存”“这张图”“我标出来了”。
- **校正转写**：图表预告及需要画面解释的名单、数字等内容；按校正后的地名查找，避免原始转写错字导致遗漏。
- **正文引用**：正文对视频画面内容的引用说明；同图多帧时结合正文重点选择。
- **景色线索**：正文、作者字幕或校正转写介绍的地点与景色，结合已有探测拼图定位对应片段。地点与画面须有明确对应依据，不将文字附近的任意风景归于该地点。首次理解同时处理这些线索，不因当前问题未要求配图而遗漏。
- 动态图从收尾口播、绘制结束或总览展示定位完整版本，不从起始底图逐段读取。

#### 5.2 抽取候选帧并生成拼图

信息图卡与风景片段使用相同的抽帧、拼图流程。静态画面先取一个时间点；需要窗口探查时，仅抽取候选展示段。两种方式均先拼图再筛选。

```bash
# 静态图卡先取一个候选时间点
python3 -I "$SITE/scripts/frame_grab.py" "$V" "$N/digest/scratch/candidates" --at <秒数>
# 需要查看候选展示段时，限定窗口抽帧
python3 -I "$SITE/scripts/frame_grab.py" "$V" "$N/digest/scratch/candidates" \
  --window <start>:<end> --step 3
python3 -I "$SITE/scripts/sheet.py" "$N/digest/scratch/candidates" \
  "$N/digest/scratch" --prefix candidate-contact
```

```text
Read 生成的 candidate-contact-*.jpg 拼图，不逐张读取候选帧
```

- 拼图使用默认 480 px/格，不提高每格分辨率。

#### 5.3 筛选信息帧与风景画面

- **用途选择**：信息帧提供主题相关、有价值的信息，如路线图、路况或景点导航；风景画面用于展示有明确地点依据的代表性景色。信息帧仅精读文字未覆盖的信息或需要核对的矛盾，风景画面根据拼图与文字选片，不作信息精读。
- **内容排除**：推广、无主题展示价值、模糊或明显遮挡的画面不选入，不为确认排除另行抽帧或裁切。无法确认地点的风景画面不作为景点照保存。
- **择优去重**：信息帧优先完整、清晰的版本；已覆盖其他帧时不再精读重复版本，内容缺失或看不清时才读对应补充帧。风景画面择优保留清晰、有代表性的版本，同一地点近似画面只选一张；仅在视角或景色有区别时选第二张。不为凑数扩大窗口或全片加密抽帧。

**输出**：选中画面的编号、时间点、用途（信息精读或风景展示）及描述；风景画面同时记录对应地点与依据。

### 6. 理解信息帧，保存选中画面与文档

精读选中的信息帧，结合口播与字幕提炼；风景画面沿用拼图筛选结果保存。

**输入**：步骤 5 选中的信息帧与风景画面、`digest/assets/transcript.md`、正文信息。

#### 6.1 精读选中的信息帧

```text
Read $N/digest/scratch/candidates/<选中的文件>
```

- **提取有价值的信息**：结合笔记主题，提炼对旅行决策有价值的信息，例如路线、路况、景点导航等。
- **直接查看画面**：使用多模态理解，不用 OCR 纯文本代替画面阅读。
- **按需裁切放大**：有价值的信息过小、无法辨认时，仅裁切对应区域后查看；仍无法确认则保留存疑，不反复裁切或放大。

```bash
# 裁切区域与倍数按实际需要填写
python3 -I "$SITE/scripts/frame_grab.py" "$V" "$N/digest/scratch" \
  --at <秒数> --crop <W:H:X:Y> --scale <倍数>
```

#### 6.2 综合口播与画面，核对信息

- 综合图卡与口播，不能只使用其中一侧；两者可能分别提供站序、距离、换乘，以及机位、理由、穿搭或窗口期等信息。
- 核对依据优先级：作者定稿图卡 → 作者字幕 → 口播 → ASR 转写；平台 AI 摘要不采纳。
- 图卡数字与单位也可能有笔误，使用前核对量级。图卡与口播冲突时优先采用定稿图卡并注明分歧；无法可靠判断时保留存疑。

#### 6.3 筛选保留画面并生成文档

- **信息帧门槛**：仅保留主题相关、信息清晰且有价值的帧；无法可靠理解的混乱信息不进入关键内容，局部存疑不影响使用时保留并注明。
- **重复与阶段帧**：在信息足够的前提下最小化保留帧数，不因精读过就全部写入；重复信息保留较完整、无遮挡的版本，同一动态图优先完成态。仅当完成态缺少不可替代的有价值细节时保留阶段帧，并标明阶段时间；不将阶段信息写成完成态可见内容。
- **风景画面**：沿用步骤 5 的拼图筛选结果，每个已确认地点保留 1–2 张有代表性且不重复的画面；不逐张精读、裁切放大或重新查找。
- **数量与查找范围**：全片不超过 10 张信息关键帧，不凑数量；阶段帧仍不能解决问题时，不无依据扩大窗口或反复加密抽帧，未找到完整图也不拼凑。
- **无有效内容**：无有效信息帧或口播时省略对应小节；只有可用景色时保留景色概括与风景附录；信息与风景均无有效内容时仅写简短说明。采集或读取失败另行说明。

仅保存最终选中的画面：信息帧复制到 `digest/assets/frames/`，风景画面复制到 `digest/assets/scenery/`，使用已选中的完整候选帧，不重复抽取；其他候选与核对帧留在 `digest/scratch/`。

**输出文档**：`digest/video.md`，按 [format-video.md](format-video.md) 编写。信息精读结果进入“关键帧”，选中的风景画面进入“附录：风景画面”，登记文件、时间点、地点与对应依据、简短景色说明及已知季节或时段。风景画面不计入信息关键帧的 10 帧上限；没有合适风景画面时简要说明，不补齐形式。

### 7. 阅读评论，提炼补充与校正信息

阅读已采集评论，补充正文与视频信息并记录争议。

**输入**：`comments.json`、已理解的正文与视频信息。

```text
Read $N/comments.json
```

| 评论类型 | 处置 |
|---|---|
| 作者回复或置顶的追加说明 | 作为一手信息，可信度约等于正文 |
| 含价格、运营或实操细节等具体信息的评论 | 采纳，多人佐证优先 |
| 对正文或视频说法的质疑、纠正 | 有回应以回应为准，未获回应标“有争议” |
| 情绪、夸赞、无关内容、平台 AI 摘要或明显机器评论 | 略过 |

- 只提炼主题相关、可供旅行决策使用的具体信息；不收主观偏好、无结论的碎片或仅复述个人游历的评论。
- 按已采集范围和点赞排序选择性阅读，不采集全量评论。
- 与当前问题相关的争议同时列入报告的“缺口与待确认”。

**输出文档**：`digest/comment.md`，按 [format-comment.md](format-comment.md) 编写。

### 8. 汇总全部有效信息，生成笔记提炼

综合正文、视频和评论，统一生成笔记级提炼。

**输入**：`note.json`、`digest/video.md`、`digest/comment.md` 及前序步骤获得的信息。

#### 处置逻辑

- **综合已有信息**：总结、关键信息与标签均综合正文、有效口播、字幕、关键帧及评论中的主题相关信息。
- **保留信息范围**：不扩大地点、时间或数值范围；保留来源差异、适用条件与争议。
- **接受无有效信息帧**：使用已有有效正文、口播与评论完成汇总，不为补齐形式继续抽帧。

#### 提炼信息指南

- **一句话总结**：概括笔记讲什么、提供哪些主要信息，便于判断是否值得取用；直接写内容，不写素材形式、提炼过程或评价。
- **关键信息**：按主题整理主要结论，保留适用时段、条件与限制；合并重复信息，排除题外内容和零散细节，不将存疑说法写成确定结论。
- **内容标签**：提炼可检索的信息类别，如游玩路线、乘车换乘；不使用泛地点、泛时节、评价词或单条具体结论。平台标签仅作参考，同类合并，通常 5–8 个，不凑数。

**输出文档**：`digest/note.md`，按 [format-note.md](format-note.md) 编写。给了问题时，后续报告按 [format-report.md](format-report.md) 从档案中取用。

## 纪律

- **视觉理解只执行一次**：已有图片或视频存档直接复用，不因问题变化或信息不足重新执行管线或重做精读。

- **中间产物只落 `digest/scratch/`**：音频、探测帧、字幕长图、候选帧及临时裁切放大图均放此处，笔记根目录不留自生成文件。
- **长期素材落 `digest/assets/`**：原始转写、校正记录、可读全文及最终保留的关键帧与风景画面；最终提炼文档落 `digest/`。
- **保留原始文件**：不改写 `note.json`、视频原件或 `asr-raw.txt`；校正另行记录。
- **限定读取范围**：只读取当前步骤指定的内容，不额外读取无关文件，例如 `downloads.json`。
- **统一生成笔记提炼**：前序步骤不零散写入 note.md，最后综合正文、视频和评论生成。
