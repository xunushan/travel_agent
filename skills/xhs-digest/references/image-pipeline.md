# 图文管线（四步）→ image.md + note.md

**先用低代价把"哪里可能有信息"定位出来，再花视觉 token 读原图。**

---

## ① 正文先行

**只读 `note.json` 的正文**，在此之前别碰同目录其它文件。产出三样东西：

**a. 主旨** —— 用标题＋正文定出这篇在讲什么（路线攻略／感受分享／票价信息／…）。
**后面读图只取能体现这个主旨的内容**，这是第③步不写流水账的前提。
**调用时给了问题的，这里连带看清问题线索**——问题里的关键词（目的地、季节、天数、
要点的类型）指明的方位，读图与落笔时重点挖；但**不拿问题去裁剪主旨**，
与问题无关、读者用得上的照样提炼；

**b. 关键信息** → 写进 `digest/note.md`（见 [format-note.md](format-note.md)）。
注意 `note.md` 的**"一句话总结"与"内容标签"要等第③步读完图卡之后再落笔**，
它们得把图卡里读出来的内容综合进去；

**c. 每张图的初判** —— 逐条看正文怎么描述图：

| 正文对图的描述 | 处置 |
|---|---|
| 只说"拍了/看了 X"（风景照） | **不读**。文字已覆盖，图无增量 |
| 说"图上标了/画了/列了/写了…"（信息在图上） | **必读**，此时才需要解决"图N 对应哪个文件" |
| 完全没提 | **交给第②步的探查决定** |

**"正文点名"不等于"值得读"**：正文已把该图内容用文字说完的（点了名的风景照），第①步就否决。
反过来，**值得读也完全不依赖正文点名**——见第②步。

## ② 拼图探查

全部图拼成低清总览（480 px/格，角标编号），**自己作为多模态模型看一遍**：

```bash
python3 -I "$SITE/scripts/sheet.py" "$N/images" "$N/digest/scratch" --prefix contact
```

这一步同时完成三件事：

1. **找出"信息在图上"的图**（地图、导览图、路线图、行程单、票价表、时刻表、清单、
   带文字批注的示意图、汇总截图）——不依赖正文是否提到；
2. **确认正文点名图的实际内容**（第①步判了"必读"的，在这里对上哪一格）；
3. **给配图选片**——美照在拼图分辨率下就能挑，**选片是"选"不是"读"，不必开原图**。

把**逐张判型表**写进 `digest/image.md` 的**附录：全部图片**（文件 / 类型 / 一句话内容）——
**逐张都要写，不许只写挑出的那几张**。判型表是"登记"，不是正文，**放在文档最末尾**；
**只登记读者能用的信息**，不写拼图路径、角标、判型规则这些方法性内容。

**分辨率取舍**：480 px/格；单张拼图设上限（脚本默认 2400×1600），图多自动拆张——
**别让拼图本身涨成"又读了一遍原图"**。

## ③ 定点原图

只把第②步判出的**信息图卡**送原图读，解读写给 `digest/image.md`（引用 `images/` 原路径，不复制）：

- **信息图卡全部精读**，无论正文提不提；
- **记录照片一律不精读**，用途只剩拼图选片与反向印证季节/场景——没有例外；
- **按第①步定的主旨组织，不按图面顺序抄**：一张导览图上印着几十个名字，全抄下来是流水账。
  先问"这篇的主旨需要图上的什么"，只写**能体现主旨**的那几个方面
  （导览图＋路线攻略主旨 → 路线、上下车标注；若主旨含打卡，再加打卡点标记），
  别的观测点、图标、装饰一律不取（见 [format-image.md](format-image.md)）；
- 写**版式关系**而不是散词：距离数字要带对应站名、标注要带位置关系、表格按行列还原。
  用多模态直接看，**不用 OCR 文本代替**。小字看不清就裁切放大后重读（放大图落
  `digest/scratch/`），不要猜；
- **转成文本后要一眼可读**：逐项属性写成 `站名＝值` 竖着列，**不要照搬图上版式**把项目名和值
  拆成两列、逼读者数第几个去对应；
- **写内容，不写过程**：不写"本篇的主旨是…"、不写读了几张、不写怎么判的型、
  不引 `digest/scratch/` 这类内部路径。

**"图N"的编号不能直接当文件序号用**（偏移量不固定）——只有确实需要定位"信息在图上"那类图时
才处理这个子问题。

## ④ 评论

按 [评论四类处置](#评论的四类处置) → `digest/comment.md`。

---

## 评论的四类处置

**评论的角色 = 正文的补充与校正，不是独立信息源。**

| 评论类型 | 处置 | 落到哪 |
|---|---|---|
| 作者的回复/置顶（价格、规则、时间的追加说明） | 一手信息，可信度≈正文 | `comment.md` 补充事实，标"评论·作者" |
| 含具体信息的评论（价格、开放时间、实操细节） | 采纳，多人佐证优先 | `comment.md` 补充事实，标"评论" |
| 对正文说法的质疑/纠正 | 有回应→以回应为准；**未获回应→标"有争议"** | `comment.md` 争议点；与当前问题相关的同时进报告缺口 |
| 纯情绪/夸赞/无关；平台 AI 生成的摘要（`@点点` 这类） | 略过 | — |

两条纪律：**读序固定在精读之后**；**范围默认前 N 屏＋高赞**——按 `comments.json` 实际采到的
条数与点赞排序取，不全滚。

---

## 复现清单

| 步骤 | 命令 | 备注 |
|---|---|---|
| 1. 正文 | Read `note.json` | 只读正文，先别碰同目录其它文件；**定出主旨**，并记下每张图的处置判据 |
| 2. 拼图探查 | `python3 -I "$SITE/scripts/sheet.py" "$N/images" "$N/digest/scratch"` | 480 px/格、角标编号；图多自动拆张 |
| 3. 定点原图 | Read 单张原图 | 只读判出的图卡；**按主旨提炼**；多模态读，不用 OCR |
| 4. 评论 | Read `comments.json` | 排在精读之后 |
| 5. 产出 | `note.md` / `image.md` / `comment.md` | 按 `format-*.md` 的结构 |

**中间产物只落 `digest/scratch/`**（拼图、临时裁剪放大图），笔记根目录不留任何东西；
删掉重跑即可。

`downloads.json` 不进上下文。重复图（`source` 是 `background-image` 的那类）由 downloader 侧过滤，
**digest 不去重**。
