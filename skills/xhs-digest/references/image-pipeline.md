# 图文管线（四步）→ image.md + note.md

**先用低代价把"哪里可能有信息"定位出来，再花视觉 token 读原图。**

---

## ① 正文先行

**只读 `note.json` 的正文**，在此之前别碰同目录其它文件。产出三样东西：

**a. 主旨** —— 用标题＋正文定出这篇在讲什么（路线攻略／感受分享／票价信息／…）。
**读图只取能体现主旨的内容**，第③步靠它不写流水账。
**给了问题时，主旨照定，问题只决定重点**——问题里的关键词（目的地、季节、天数、要点类型）
指明的方位多挖多写，读者用得上的其它信息照样提炼；

**b. 关键信息** → 写进 `digest/note.md`（见 [format-note.md](format-note.md)）。
注意 `note.md` 的**"一句话总结"与"内容标签"要等第③步读完图卡之后再落笔**，
它们得把图卡里读出来的内容综合进去；

**c. 每张图的初判** —— 逐条看正文怎么描述图：

| 正文怎么提图 | 处置 |
|---|---|
| **引用了某张图**（"路线图见 12"、"图上标了/画了/列了…"、"拍了 X（图 15）"） | 先按正文的描述判**它指向的是不是一条具体事实**：是 → 记下"它在拼图里是哪一格"，到第②步在拼图上判型、判价值，再决定读不读；不是 → 不读 |
| 完全没提 | 记下"待第②步判"，交给拼图 |

判的就是**正文怎么描述它**："路线图见 12"指向图上有一条具体事实，
"拍了树正群海（图 15）"只有观感和选片价值。正文引用给的是"去哪一格找"，不是"必读"；
正文只字未提的图卡照样在第②步挑出来。编号 ≠ 文件序号，定位时拿正文描述去 `images/` 里比对（见第③步）。

## ② 拼图探查

全部图拼成低清总览（480 px/格，角标编号），**自己作为多模态模型看一遍**：

```bash
python3 -I "$SITE/scripts/sheet.py" "$N/images" "$N/digest/scratch" --prefix contact
```

这一步同时完成三件事：

1. **找出"信息在图上"的图**（地图、导览图、路线图、行程单、票价表、时刻表、清单、
   带文字批注的示意图、汇总截图）——无论正文提没提；
2. **对上正文引用的那张图是哪一格**（第①步记下的）；
3. **给配图选片**——美照在拼图分辨率下就能挑。**选片是"选"，在拼图上完成，不开原图**。

**逐张判型表**（文件 / 类型 / 一句话内容）写进 `digest/image.md` 最末尾的
**附录：全部图片**——**每张图一行，读过的、没读的都写**。附录是登记，
只写读者能用的信息（拼图路径、角标、判型规则这类方法性内容不进附录）。

**分辨率取舍**：480 px/格；单张拼图设上限（脚本默认 2400×1600），图多自动拆张——
拼图的分辨率要低于"读原图"的量级。

## ③ 定点原图

**开原图的判据**：**这张图上有一条读者能拿去用的具体事实吗？** 指得出是哪一条、适用范围
也对得上（时节／地点／口径）就精读；只有观感、或条件不符只在附录登记。拿不准的打开看。
精读结果写给 `digest/image.md`（引用 `images/` 原路径，不复制）：

- **记录照片不精读**，只用于配图选片和印证季节/场景；
- **按主旨组织，不按图面顺序抄**：先问"主旨需要图上的什么"，只写**能体现主旨**的那几个方面
  （导览图＋路线攻略主旨 → 路线、上下车标注；主旨含打卡，再加打卡点标记）；
  观测点、图标、装饰不取（见 [format-image.md](format-image.md)）；
- **写版式关系**：距离数字带对应站名、标注带位置关系、表格按行列还原。**用多模态直接看**，
  不用 OCR 文本代替；小字看不清就裁切放大后重读（放大图落 `digest/scratch/`）；
- **转成文本要一眼可读**：逐项属性写成 `站名＝值` 竖着列。照搬图上版式（项目名与值分两列、
  靠位置对应）会让读者数格子；
- **只写内容**：方法、过程、内部路径不进 `image.md`——"本篇的主旨是…"、读了几张、
  怎么判的型、`digest/scratch/` 路径都属此列。

**"图N"编号对不上文件序号**（偏移量不固定）：拿正文对该图的描述去 `images/` 里比对定出文件，
按编号硬算会读错图。

## ④ 评论

按 [评论四类处置](#评论的四类处置) → `digest/comment.md`。

---

## 评论的四类处置

**评论的角色 = 正文的补充与校正。**

| 评论类型 | 处置 | 落到哪 |
|---|---|---|
| 作者的回复/置顶（价格、规则、时间的追加说明） | 一手信息，可信度≈正文 | `comment.md` 补充事实，标"评论·作者" |
| 含具体信息的评论（价格、开放时间、实操细节） | 采纳，多人佐证优先 | `comment.md` 补充事实，标"评论" |
| 对正文说法的质疑/纠正 | 有回应→以回应为准；**未获回应→标"有争议"** | `comment.md` 争议点；与当前问题相关的同时进报告缺口 |
| 纯情绪/夸赞/无关；平台 AI 生成的摘要（`@点点` 这类） | 略过 | — |

两条纪律：**读评论排在精读之后**；**读前 N 屏＋高赞**——按 `comments.json` 实际采到的
条数与点赞排序取，不滚全量。

## 复现清单

| 步骤 | 命令 | 备注 |
|---|---|---|
| 1. 正文 | Read `note.json` | 只读正文，先别碰同目录其它文件；**定出主旨**；正文引用的图按描述判有无价值信息，**有价值的记下"在拼图里对准哪一格"** |
| 2. 拼图探查 | `python3 -I "$SITE/scripts/sheet.py" "$N/images" "$N/digest/scratch"` | 480 px/格、角标编号；图多自动拆张 |
| 3. 定点原图 | Read 单张原图 | 只读判出的图卡；**按主旨提炼**；多模态读，不用 OCR |
| 4. 评论 | Read `comments.json` | 排在精读之后 |
| 5. 产出 | `note.md` / `image.md` / `comment.md` | 按 `format-*.md` 的结构 |

**中间产物只落 `digest/scratch/`**（拼图、临时裁剪放大图），笔记根目录不留任何东西；
删掉重跑即可。

`downloads.json` 不进上下文。重复图（`source` 是 `background-image` 的那类）由 downloader 侧过滤，
**digest 不去重**。
