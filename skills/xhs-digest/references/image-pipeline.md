# 图文笔记理解管线

## 原则

**先以低成本确定哪些图片需要精读，最小化原图读取次数。**

## 执行步骤

以下 `$SITE` 为 skill 根目录，`$N` 为笔记目录，均使用绝对路径。`Read` 表示读取文件或以多模态查看图片，不是 shell 命令。

### 1. 阅读正文，确定主题与图片线索

读取标题与正文，确定主题、正文信息及图片引用线索。

**输入**：`note.json` 的标题与正文、用户问题与要求（如有）。

```text
Read $N/note.json
```

- **确定主题**：根据标题与正文判断笔记主要内容，后续图片理解与笔记提炼均围绕该主题。
- **利用问题线索**：提供问题时，结合其中的目的地、时间、路线及关注事项，在笔记主题范围内优先筛选、理解和总结相关信息。
- **保留正文信息**：供最后汇总使用；与主题无关的零散信息不提炼。
- **识别图片线索**：正文指向有价值的信息的引用，留待拼图定位；仅描述风景或观感的引用，不构成精读要求。
- **保留探查范围**：正文未提及的图片仍通过拼图判断。

**输出**：主题、正文信息与待核对的图片线索。

### 2. 查看低清拼图，筛选候选图片

将图集拼成低清总览，一次完成候选筛选、引用定位和配图选择。

**输入**：`images/`、步骤 1 的主题与图片引用说明。

```bash
python3 -I "$SITE/scripts/sheet.py" "$N/images" "$N/digest/scratch" --prefix contact
```

```text
Read 生成的 contact-*.jpg 拼图
```

- **定位引用**：结合正文描述、拼图内容与角标，确定引用对应的文件。
- **选择配图**：记录照片仅在拼图上选片或印证季节、场景，不另开原图精读。
- **限制分辨率**：使用脚本默认的 480 px/格，不提高每格分辨率。

#### 精读图片筛选规则

- 选择能提供主题相关、有价值信息的图片，例如路线图、导览图、行程单、票价表、时刻表或带批注的示意图。
- 结合拼图与正文引用说明，确定需要从原图获取或核对的信息；正文未引用的图片同样参与筛选。
- 推广/活动图、无主题信息的记录照片、装饰文字及已被完整版本覆盖的重复图不选入精读，不为确认其内容另开原图或裁切放大。
- 其他图片仅根据拼图与正文引用说明整理描述，不读取原图。

**输出**：需要精读的图片编号，以及根据拼图与正文引用说明整理的图片描述。

### 3. 读取选中的原图

读取步骤 2 选中的原图，理解主题相关的信息及其对应关系。

**输入**：步骤 2 选中的 `images/` 文件、拼图及正文引用说明。

```text
Read $N/images/<选中的文件>
```

- **提取有价值的信息**：结合笔记的主题，提炼对读者做旅行决策有价值的信息，比如路线图、路况、景点导航等。
- **核对矛盾与缺漏**：与正文及其他有效图片对照，识别信息不一致或未交代清楚之处，不猜测无法确认的内容。
- **直接查看图片**：使用多模态理解文字、位置和对应关系，不用 OCR 提取的纯文本代替图片阅读。
- **按需裁切放大**：原图中有价值的信息过小、无法辨认时，裁切并放大对应区域后查看；仍无法确认则保留存疑，不连续尝试裁切或放大。

#### 写入 image.md 的筛选规则

- 仅保留主题相关、信息清晰且对旅行决策有价值的图片。
- 信息重复时，保留较完整、清晰的版本；其他图片仅在提供额外有价值信息时保留。
- 核对后仍信息混乱、无法可靠理解的图片不进入关键内容；局部存疑不影响主要信息使用时，保留并注明存疑。
- 无图片符合要求时，“信息图卡”仅写无有价值信息的说明；读取失败另行说明。
- 全部图片的简短描述仅依据拼图与正文引用说明生成，不为填写附录读取原图。

**输出文档**：`digest/image.md`，按 [format-image.md](format-image.md) 编写关键图片信息、附录及无有效图卡时的说明。

### 4. 阅读评论，提炼补充与校正信息

在图片精读之后阅读已采集评论，补充正文信息并记录影响取用的争议。

**输入**：`comments.json`、已理解的正文与图片信息。

```text
Read $N/comments.json
```

#### 评论的四类处置

| 评论类型 | 处置 |
|---|---|
| 作者回复/置顶的价格、规则、时间等追加说明 | 作为一手信息，可信度约等于正文 |
| 含价格、开放时间、实操细节等具体信息的评论 | 采纳，多人佐证优先 |
| 对正文说法的质疑或纠正 | 有回应以回应为准；未获回应标“有争议” |
| 情绪、夸赞、无关内容及平台 AI 摘要、明显的机器评论 | 略过 |

- 只提炼主题相关、可供旅行决策使用的具体信息，如规则、价格、运营方式、位置和时长；不收主观偏好、无结论的碎片或仅复述个人游历的评论。
- 按已采集范围和点赞排序选择性阅读，不为本步骤滚动采集全量评论。
- 与当前问题相关的争议同时列入报告的“缺口与待确认”。

**输出文档**：`digest/comment.md`，按 [format-comment.md](format-comment.md) 编写。

### 5. 汇总全部有效信息，生成笔记提炼

综合正文、图片和评论，统一生成笔记级提炼。

**输入**：`note.json`、`digest/image.md`、`digest/comment.md` 及前序步骤获得的信息。

#### 处置逻辑

- **综合已有信息**：一句话总结、关键信息和内容标签均综合正文、有效图片及评论中的主题相关信息，不能仅复述正文或仅使用某一侧内容。
- **保留信息范围**：不扩大地点、时间或数值范围；评论来源与争议按对应文档规则处理。
- **接受无有效图片**：无图卡时使用有效正文和评论完成汇总，不为补齐形式继续读图。

#### 提炼信息指南

- **一句话总结**：概括笔记讲什么、提供哪些主要信息，使读者能快速判断是否值得取用。直接写内容，不写素材形式、提炼过程或“干货丰富”等评价。
- **关键信息**：按主题整理影响旅行决策的主要结论，保留适用时段、条件和限制；合并重复信息，排除题外内容和零散细节，不把存疑说法写成确定结论。
- **内容标签**：提炼可用于检索的信息类别，如游玩路线、乘车换乘、徒步路段；不使用泛地点、泛时节、评价词或单条具体结论。平台话题标签仅作参考，不照抄；同类合并，通常 5–8 个，信息不足时不凑数。

**输出文档**：`digest/note.md`，按 [format-note.md](format-note.md) 编写。给了问题时，后续报告按 [format-report.md](format-report.md) 从档案中取用。

## 纪律

- **视觉理解只执行一次**：已有图片或视频存档直接复用，不因问题变化或信息不足重新执行管线或重做精读。

- **中间产物只落 `digest/scratch/`**：拼图、临时裁切与放大图均放此处，笔记根目录不留自生成文件。
- **最终产物落 `digest/`**：image.md、comment.md、note.md 按各自格式编写；图片原件保留在 images/，不移动、不改名。
- **限定读取范围**：只读取当前步骤指定的内容，不额外读取无关文件，例如 `downloads.json`。
- **保留原始文件**：不改写下载器保存的 `note.json`；提炼结果写入 `digest/note.md`。
- **统一生成笔记提炼**：前序步骤不零散写入 note.md，最后综合正文、图片和评论生成。
