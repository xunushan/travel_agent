# 报告结构契约（**仅当给了问题**）

报告是**问题级**的，随问题重生成；档案是**笔记级**的，只增不改。
报告只读 `digest/*.md`（不够时定向补读并增补档案），**不重跑管线**。

## 骨架（固定三节，不增不减）

```text
# 笔记整理报告：<标题>
[一行溯源：noteId / digest 路径 / 存档本次新生成还是复用 / 整理目的=当前问题]

## 1. 与问题相关的总结   ← 按问题维度分小段写全结论本体；只读本节应能回答本次问题
                           每条结论标注来源（正文/图卡/帧/评论）
## 2. 关键素材           ← 与本问题相关的图卡/关键帧/美照：本地路径 + 一句话
## 3. 缺口与待确认       ← 只列会改变决策、且要再拿信息去确认的；按重要性排列
```

## 五条约定（防随意发挥）

1. **报告只对当前这一篇负责**——**不与其他笔记做对比、不做交叉引用**（不写"另一篇的
   价值在…""可借另一篇做交叉"）。跨笔记的汇总与取舍是 `xhs-search` 的职责；
2. **§1 写全不写略**——每个问到的维度成段写出**结论本体**，不是覆盖清单。
   **判据：读者只读 §1 就应该能回答本次问题**；
3. **§2 只列关键素材**：图卡引 `images/` 原路径、关键帧引 `digest/assets/frames/`，
   每条一句话说清"它有什么用"。**内容不在这里重写**——正文在 `image.md`/`video.md` 里；
4. **§3 只留会改变决策的缺口**（见下）；
5. **不写建议搜索词**（那是 `xhs-search` 的职责）；**不另开"可信度与存疑"节**——
   所有"觉得不对、需要再确认"的点一律进 §3。

**与笔记无关的信息不进报告**：吃/住/停车这类当前问题没问到的，留在档案里。
**缺口 = 会影响本次决策的不确定，不是信息清单。**

## §3 的写法

先过一遍筛子：这条缺口**会不会改变本次决策**？要再拿什么信息才能确认？
**答不上来的不列**——宁少勿滥。

**按重要性排列**（最可能颠覆方案的在最前），每条三项：

| 缺口内容 | 缺口类型 | 相关证据 |
|---|---|---|
| <缺什么、要拿什么信息去确认> | 见下表 | <档案里的出处：哪一帧 / 哪句口播 / 哪条评论> |

| 缺口类型 | 用在什么时候 |
|---|---|
| 数据缺失 | 档案里根本没有这项数据 |
| 单一来源 | 只有一处说过，没有第二条能交叉验证 |
| 口径不一 | 两处说法不同，还没定谁对 |
| 前提未证实 | 方案的成立依赖一个没被证实的假设 |
| 时效不匹配 | 数据是真的，但不是本次出行时段的 |

## 示例

```text
# 笔记整理报告：一个真正的九寨沟攻略，这才是一个攻略

溯源：6ab4f9b9000000001b033e25 ｜ digest 复用（2026-10-09 生成，本次未补读）
     ｜ 整理目的：规划 10 月下旬九寨沟游玩路线、锁定最精华打卡点

## 1. 与问题相关的总结

**整体走法**：……（来源：站点图 t0393）
**点位与时段**：……（来源：汇总卡 t0306）
**10 月下旬的适用性**：……（来源：发布时间；口播）

## 2. 关键素材
- digest/assets/frames/t0306.jpg —— 作者自制"最佳时间+机位"汇总卡，可直接当时间预算表
- digest/assets/frames/t0393.jpg —— 三沟站点图，可当路线底图

## 3. 缺口与待确认

| 缺口内容 | 缺口类型 | 相关证据 |
|---|---|---|
| 7:30 能否直接坐车到镜海——整套走法的前提；须问景区或当日车上导览员 | 前提未证实 | 口播 ［06:31］「直奔镜海」；评论质疑两条，作者未回应 |
| 10 月下旬的实际日落时刻——决定树正群海、芦苇海那两段还有没有光 | 数据缺失 | 唯一的日照数据是 2024 年 11 月（日出 07:21→07:48、日落 18:11→17:56） |
| 窗口期边界 10/15 是否成立 | 单一来源 | 只在口播出现；汇总卡与站点图均无日期标注 |
```
