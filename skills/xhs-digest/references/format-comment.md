# `digest/comment.md` 结构契约

**评论的角色 = 正文的补充与校正，不是独立信息源。** 只收
[评论四类处置](image-pipeline.md#评论的四类处置)里的前三类。

## 骨架

```text
# 评论提炼

## 补充事实
- <客观事实> —— 评论·<作者>（或"评论"）；多人佐证的注明

## 争议点
- <争议点> ｜ 说法：<谁说的> ｜ 质疑：<谁、质疑什么> ｜ 作者是否回应：<有/无> ｜ 倾向结论：<…>
```

## 补充事实

**只收客观事实**——可核实的规则、价格、开放与停运、运营方式、位置、时长这类，
读者能直接拿去用。**一条一事**，一句话说完，按主题分行（票务 / 交通与运营 / 景点 / 安全）。

收进来之前先问一句"这是事实还是感受"：

| 收 | 不收 |
|---|---|
| 观光车 90 元/人、当日不限次 | 作者最喜欢芦苇海（**主观偏好**） |
| 早晨坐车按人流实时调度，三条线随机分配 | 有评论者 8 点进沟 16 点逛完（**他人游记式佐证**） |
| 镜海站能下车，往上走不能上车 | 「宝藏攻略」「mark 了」（**情绪／无信息**） |
| 九寨不反、黄龙会反 | 「10 月 29 去的」这类**没有结论的碎片** |

**同一事实多人提及要注明**（`评论（3 人提及）`）。
**作者的回复标「评论·作者」**，可信度≈正文。

## 争议点

只写**会改变取用决定**的分歧。四要素写全，**每条控制在 3–5 行**：

- **说法**：谁在哪说的（作者 → 正文/口播/图卡；评论 → 评论·某）；
- **质疑**：谁、质疑什么，**只引关键那一句**，不复述整条评论；
- **作者是否回应**：有就写回应内容，没有就明写「未回应」；
- **倾向结论**：**作者没回应的必须标"有争议"**，不能替作者下结论；能靠档案里的
  硬证据（图卡、字幕）判断的，写清倾向并给出依据。

**不铺陈过程、不写分析长段**——详细推理进报告 §3，这里给结论。

## 两条纪律

- **过滤 AI 评论**：平台 AI（如 `@点点`）生成的摘要、以及明显的机器评论，**一律不收**。
- **与当前问题相关的争议，同时要进报告的 §3 缺口**。

## 示例

```text
# 评论提炼

## 补充事实

**票务**
- 观光车 90 元/人，当日不限次乘坐 —— 评论·作者

**交通与运营**
- 早晨坐车按人流实时调度，左/中/右线随机分配，不一定能直奔某个点 —— 评论（2 人提及）
- 镜海站能下车，但从镜海往五花海（往上走）不能再上车，只能坐回诺日朗再往右线走 —— 评论

**安全**
- 九寨沟基本不高反，黄龙会高反 —— 评论（2 人提及）

## 争议点

- **7:30 能否直奔镜海** ｜ 说法：作者口播「7 点半入场，直奔镜海」｜
  质疑：评论称「早晨坐车按人流调度、中左右线随机分配」，「坐车不停怎么办」——**作者未回应** ｜
  倾向结论：**有争议，且倾向前提不成立**；若被分到左线或中线，「从后往前玩右线」的顺序要现场重排。
```
