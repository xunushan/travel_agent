# 视频理解方案调研

> 调研目的：阶段 0/1 汇总环节需要理解小红书视频型笔记（概括类笔记中视频占比不低，且视频笔记正文往往很薄）。
> **重要前提：主 Agent 使用的大模型是多模态大模型**——不需要另配视觉模型；若模型支持原生视频输入，短视频可整段直送。

## 结论

1. **分级处理，先用最便宜的**：封面+标题+评论能解决的不碰视频本体；
2. **主模型是多模态，链路大幅简化**：抽帧/字幕直接送主模型，不需要单独接视觉模型 API；
3. **有现成开源 Skill 可直接装**（见第三节），不用从零造轮子。

## 一、分层方案（按多模态主模型调整）

| 档位 | 做法 | 成本 | 什么时候用 |
|---|---|---|---|
| **L1 近似判断（默认）** | 封面图 + 标题 + 正文 + 评论（高赞评论常含路线信息） | 极低 | 阶段 0 的大多数情况——概括类问题信息密度要求不高 |
| **L2 抽帧+转写** | ffmpeg 抽关键帧（可拼 contact sheet）+ ASR 字幕 → 送**主多模态模型** | 中 | 某题闭合不了、且候选以视频为主时升级 |
| **L3 整段直送** | 视频文件直接送主多模态模型（前提：模型支持原生视频输入） | 中~高 | 小红书视频多为几十秒~几分钟，若模型支持视频输入，这档其实很便宜；阶段 1 看游览动线时更常用 |

## 三、工程要点（来自 claude-video 等实践）

- **上下文/token 控制靠帧预算**：10 分钟视频 1fps 也有 600 帧（约 60 万 token），必须设帧预算；小红书短视频压力小很多，但批量时仍要控制；
- **场景感知抽帧优于均匀抽帧**：视频信息分布不均匀，均匀抽帧既漏重点又产生冗余；claude-video 的近重复帧去重也值得抄；
- **画面与语音要按时间轴对齐**：语义同时存在于画面和声音里，帧图片 + ASR 文本 + 时间戳组织成结构化数据再交给模型；
- **contact sheet 技巧**：把抽出的关键帧拼成一张大图送模型，一次调用看多帧（借自 guizang-social-card-skill 的 Live Photo 分支）；
- **分级调用省成本**：L1 能答就不抽帧；ASR/OCR 文字能答就不送图。

## 四、建议落地顺序

1. 阶段 0 先只跑 L1，验证覆盖率；
2. 遇到"视频候选闭合不了问题"的实际情况 → **直接装 claude-video**（或参考 video-recap-skills 的 video-understanding 子技能）实现 L2，产物送主多模态模型；
3. 确认主模型是否支持原生视频输入：支持则 L3 变为"短视频整段直送"，参考 sansheng-gemini-video 的下载与调用方式。
