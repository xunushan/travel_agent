# 单景点调研设计方案

## 1. 定位与输入输出

围绕一个景点建立游览认知，提供点位、玩法、到达方式、住宿与政策等参考信息，帮助用户自行选择点位、比较游览方式并规划行程。景点可以包含多个观景点、村落、入口或内部游览区域。

- **输入**：单个景点名称，以及用户已表达的出行方式、时段、兴趣或其他相关情况。一次不处理多个景点。
- **输出**：《单景点游览参考》，包含整体分布、点位比较、到达与停车、参考串联方式、住宿区域、票务与风险信息，以及必要的缺口说明。
- **完成目标**：用户能够判断想看哪些点、何时去、如何到达、游览强度与大致耗时、住在哪里更方便，以及哪些事项仍需确认。

用户情况用于调整调研重点，不要求提供完整条件。自驾时重点获取车辆通行、停车与步行衔接；出行方式未知时先了解主要到达方式。只有无法明确调研对象或形成有意义的问题时才询问用户。

## 2. 流程

```text
1. 生成初始调研大纲
2. 按主题调研
3. 汇总已有信息与新发现
4. 判断缺口及是否补充调研
   需要补充 → 调整大纲，回步骤 2
5. 输出单景点游览参考
```

主 agent 设计大纲、汇总与判断缺口；每次唤起一个子 agent，使用 `xhs-search` 调研一个主题，传入问题与要求。要求包含期望信息与成功标准。主题报告与现有素材通过已有 skill 复用，不重复下载或理解存档笔记。

每个主题返回后立即检查后续问题是否已被回答，以及是否出现影响游览的新问题；不等全部初始主题结束后才调整大纲。

## 3. 调研大纲生成

先从整体分布与主要点位建立认知，再结合用户情况研究玩法与到达方式。以下方向供设计参考，按景点特点合并、拆分或省略，不固定题数，不为每个点位机械生成一套问题。

| 方向 | 期望获取的信息 | 成功标准 |
|---|---|---|
| 整体分布与游览结构 | 主要区域、点位与入口，分布图，点位间连接关系；区分自驾、景交与步行范围 | 能理解各点位的位置关系及主要游览走向，避免只能照抄他人的日程 |
| 点位看点与游览条件 | 主要点位看什么、适合的时段与季节、现场照片、游览与步行耗时、体力要求；特色景观对应的点位及出现条件 | 能比较点位差异、看点与付出，判断哪些符合兴趣；不将晨雾、云海等条件性景观写成必然出现 |
| 到达与内部交通 | 入口与点位的导航目标、交通方式、最后一段到达过程；自驾时补车辆可达范围、停车位置与收费、停车后的步行距离或时间 | 能区分导航目标、停车位置与实际点位，了解到达过程与主要障碍 |
| 参考串联方式 | 常见点位顺序、大致耗时、交通与步行衔接，早晚观景时间窗与不同游览强度 | 能比较不同参考走法的覆盖点位、强度与时间需求，不生成确定的个人行程 |
| 住宿与补给 | 可住宿的村落、片区或城镇，与入口、主要点位和早晚观景的关系；停车、餐饮与补给条件，必要的价格参考 | 能比较住在哪个区域更方便及其取舍，不代替用户选定酒店或安排入住日期 |
| 门票与进入规则 | 价格、有效期、多次进入、预约渠道与时间、开放时段、车辆或景交规则；适用的优惠政策 | 能判断怎样进入与预订、游览方式是否受规则限制，明确政策日期与适用条件 |
| 现状与风险 | 封闭、施工、道路与步道状况、天气敏感性、拥挤与停车压力，以及影响进入或游览的风险 | 能识别影响点位选择、到达与游览的主要限制，并区分近期实况与历史经验 |

照片用于比较点位的实际看点，按用途和信息差异选择；每个观景点有可用素材时提供 1–2 张代表性风景照，近似画面只保留一张。未能确认位置的图片不用于证明某点位的景色。

用户明确带宠物、行动受限或其他情况时，将相关进入政策、到达条件与游览限制纳入对应主题，不自动扩展为额外的完整调研。

## 4. 动态补充调研

补充调研不预设固定的问题清单。阅读笔记、评论及主题报告时，根据新发现的信息，站在用户实际游览的角度判断：

- 用户可能会关注或遇到什么问题？
- 当前信息是否足以支持选择，或帮助用户应对该问题？
- 信息不足是否会影响旅行决策或旅行体验？

结合景点特点、出行时段与用户情况灵活判断，关注初始大纲未覆盖的问题。新信息可能揭示限制、疑问，也可能带来值得了解的玩法或体验；不只围绕交通障碍与风险补充调研。

### 补充调研示例

以下仅展示从新信息形成补充问题的思路，不作为固定触发条件或完整清单。

| 新发现 | 补充调研方向 |
|---|---|
| 导航易错、导航终点不是入口或点位 | 具体导航目标、停车位置、下车后路径、关键岔路与辨认标志；必要时获取路线示意图 |
| 道路难走或车辆通行条件不明 | 具体困难路段、路面与道路宽度、会车条件、车型限制及近期变化；比较替代到达方式 |
| 徒步耗时或难度影响观景 | 步行起点、距离、爬升、路面、往返耗时与时段限制 |
| 点位名称、入口或到达说法冲突 | 核对是否为同一点位、不同入口或不同时间的情况；无法确认时并列说明 |
| 新点位有独立看点或可补足游览认知 | 了解其位置、看点、到达条件与通行限制，确认信息后纳入比较 |
| 住宿位置影响早晚观景或停车 | 比较相关住宿区域到点位的驾驶、停车与步行衔接，而非直接搜索酒店清单 |
| 封闭、预约或车辆政策可能改变玩法 | 针对具体规则补充现状与适用条件 |

### 补充流程

1. 检查主题报告与已有结论，能回答的直接整合。
2. 从用户角度判断该问题是否值得进一步了解：现有信息是否足够应对，信息不足是否影响旅行决策或体验。已有信息足够或影响有限时不继续展开。
3. 针对具体缺口生成补充问题，写明期望信息与成功标准，调用 `xhs-search`。
4. 将补充结果合入相关主题；必要时新增主题。重新检查信息是否足够，以及是否出现值得进一步了解的新问题，已解决的内容不重复调研。
5. 仍无法确认时，说明未解决原因、来源分歧与影响，不推测为可达或安全，也不围绕同一缺口重复发起相同调研。

### 风景照覆盖与兜底

先从主题报告素材、`digest/image.md` 附录及 `digest/video.md` 的风景画面附录选片；图文描述不足时查看已有低清拼图。汇总时检查缺图点位，缺图且影响景色比较时集中设计补充主题，尽量覆盖多个内部点位，不机械逐点搜索，也不为凑足两张反复搜索。补充后仍无可确认素材时说明缺图，旧视频存档不重跑管线补图。

## 5. 扎尕那自驾调研示例

以下是问题设计示例，不代表已经核实的景点信息，也不是固定大纲。

| 主题 | 问题 | 期望信息 | 成功标准 |
|---|---|---|---|
| 整体认知 | 扎尕那的主要村落、观景点与游览区域如何分布，通常怎样连接？ | 分布图、点位清单、主要连接道路，车辆与步行范围 | 能理解村落和观景点之间的关系，形成整体游览认知 |
| 点位比较 | 扎尕那主要观景点各看什么，适合何时游览，游览强度有何差异？ | 实景照片、看点、时段与季节条件、步行与停留耗时 | 能比较日出、晨雾、日落等观景选择及其到达代价 |
| 自驾到达 | 自驾如何进入扎尕那并到达主要观景点？在哪里停车，下车后怎样走？ | 入口与导航目标、车辆可达范围、停车位置与费用、步行衔接 | 能判断哪些点可开车接近，哪些需步行，避免只得到点位名称而不知如何到达 |
| 参考游览方式 | 扎尕那有哪些常见的点位串联方式，适合怎样的游览强度与时间需求？ | 节点顺序、交通与徒步衔接、大致时长和观景时段关系 | 能比较走法，不直接接受某篇笔记的逐日行程 |
| 住宿区域 | 扎尕那住在哪些村落或区域更方便，早晚观景、自驾停车与补给有何差异？ | 住宿分布、到主要点位的衔接、停车与补给条件 | 能根据自己倾向的观景活动比较住宿位置 |
| 进入规则与现状 | 扎尕那门票、预约、车辆进入和近期通行情况如何？ | 票务规则、有效期、预约与开放限制，近期道路或步道情况 | 能判断进入与游览的前提，明确仍需核实的事项 |

若调研发现洛克观景台导航易错，则补充研究具体导航目标、停车位置与步行入口；若同时出现“可直接导航”与“需从某村步行”的说法，核对两者对应的交通方式、起点与日期，不能任选一种作为确定答案。

若用户已明确想看日出，则到达与住宿调研优先关注清晨驾驶、停车和步行条件。若出行时段已明确，再研究对应季节的景观条件与近况，不预设一定能看到晨雾。

同样，天山石林若出现“道路难走”的调研线索，应进一步了解困难发生在哪一段、具体路面与通行条件、适用车型及近期情况；“道路难走”本身不足以支持自驾决策。

## 6. 输出内容

直接输出 Markdown，路线图与风景照在正文直接展示，不生成 HTML 或海报。《单景点游览参考》按以下内容组织：

1. **整体分布与参考线路**：点位分布图、主要入口和连接关系，参考节点顺序与大致时间需求。
2. **点位与特色景观比较**：看点、实景照片、适合时段与季节条件、游览强度及耗时；包含有依据的新发现点位。
3. **到达、停车与步行衔接**：对照到达方式提供导航与最后一段路径，自驾信息明确到停车及下车后的过程。
4. **住宿区域与补给**：住宿区域比较、到观景点的衔接、停车与餐饮条件。
5. **票务、现状与风险**：进入与预约规则，近期限制与影响游览的风险。
6. **缺口与来源**：仍影响决策的未知事项、冲突与来源。

每项结论保留适用点位、时段、交通方式与来源。导航路径优先用分步说明或示意图；不同入口与路径分别呈现，避免拼接成一条未经证实的路线。路线图、点位照片按覆盖内容与用途去重，在满足判断需要的前提下最小化数量。

## 7. 纪律

- 一次只调研一个景点；内部点位属于该景点的调研范围，不扩展为多目的地行程。
- 禁止替用户确定具体路线、编排逐日行程、选定酒店或执行预订。输出参考信息与比较依据。
- 不以“全面”为由逐点逐项无限搜索；已有信息足以支持相关旅行决策并帮助用户应对主要体验问题时停止，关键未知事项如实列出。
- 不因个别博主曾到达就认定点位安全可达；进入限制、路径或通行条件无法确认时说明不确定性，不推荐未经确认的进入方式。
- 示例中的名称、价格、导航与耗时均需通过实际调研确认，不直接作为最终答案。
