# xhs-digest 设计方案

## 1. 定位与接口

理解一篇已下载的小红书笔记，提炼笔记主题内对决策有价值的信息，生成本地 `digest/` 存档；提供问题与要求时，另从存档生成问题级整理报告。不承担搜索、下载或跨笔记汇总。

图片与视频只理解一次。问题线索用于确定主题内重点，不能以正文已能回答问题为由跳过对应媒体管线。已有存档直接复用；文本不足时允许少量回读 `note.json` 或 `comments.json`，不增补存档，不重跑媒体管线。旧视频没有风景附录时不重新抽帧补图。

## 2. 存档与报告

```text
digest/
├── note.md                 # 最后综合正文、媒体与评论生成
├── comment.md              # 评论补充与争议
├── image.md                # 图文提炼与全部图片附录
├── video.md                # 视频提炼与风景画面附录
├── assets/
│   ├── asr-raw.txt          # 原始转写，不改写
│   ├── asr-corrections.md   # 校正及依据
│   ├── transcript.md       # 校正后全文
│   ├── frames/             # 信息类关键帧
│   └── scenery/            # 有地点依据的代表性风景画面
└── scratch/                # 拼图、候选、字幕带、音频与临时裁切
```

下载器保存的 `note.json`、`comments.json`、图片与视频原件不改写。中间产物只落 `scratch/`，长期素材落 `assets/`；笔记根目录不留生成文件。

- `note.md`：一句话总结、主题关键信息与可检索内容标签，最后统一综合，不逐步追加。
- `comment.md`：作者补充、具体实操信息及争议；忽略情绪、无关内容和平台 AI 摘要。
- `image.md`：有效信息图卡的提炼与全部图片的简短描述；无有效图卡允许说明。
- `video.md`：有效信息帧、口播要点、矛盾与异常，以及“附录：风景画面”。各内容小节无有效信息可省略；风景附录无素材时简要说明。

问题报告保留相关总结、关键素材、缺口与待确认三节。总结注明存档出处；素材提供本地路径与用途；缺口说明仍影响决策的未知内容及依据。不比较其他笔记，不列全量素材。

## 3. 图文管线

1. 阅读正文，确定主题与引用线索，结合用户问题确定重点。
2. 生成默认 480 px/格的低清拼图，筛选需要精读的图片，并整理全部图片描述。
3. 精读有价值的信息图片，提炼主题内容；重叠内容优先完整版本，已覆盖且清晰时不读分图。风景照依据拼图与正文整理附录，不另开原图精读。
4. 阅读已采集评论，提炼补充与争议。
5. 综合全部有效信息生成 `note.md`。

精读后的图片仍按价值与重复关系筛选，不全部写入文档；无有效内容可简要说明。图片形态或有文字不直接构成精读条件，推广与无主题价值的画面不读取。

## 4. 视频管线

1. 阅读正文，识别主题、画面线索与问题重点。
2. 检查 ASR 依赖、提取音频并保存原始转写。
3. 抽取探测帧并拼图，判断视频形态、字幕层次及画面线索。
4. 裁切字幕带并拼接阅读，结合 ASR 核对地名、数字与漏句，保存全文及校正依据。
5. **统一定位与筛选**：正文、作者字幕、校正转写和探测拼图定位信息画面或风景片段；限定片段抽候选，生成低清拼图后择优选择。
6. 精读选中的信息帧，综合口播与画面；风景画面不作信息精读，沿用拼图筛选结果。分别保存信息帧与风景画面，生成 `video.md`。
7. 阅读评论后，综合全部有效信息生成 `note.md`。

### 画面选择与保存

信息帧提供主题相关、对决策有价值的信息，优先完整清晰的完成版本，已覆盖的重复或阶段版本不再读取。全片信息关键帧不超过 10 张，不凑数。

风景画面利用正文、字幕与笔记内容确认地点，每个已确认地点择优保留 1–2 张有代表性且视角或景色不同的画面。近似画面只留一张，无法确认地点、推广、模糊或明显遮挡的画面不保存。不另设逐帧风景阅读管线，不全片加密抽帧，不为凑齐地点扩大查找范围。

选中的信息帧落 `digest/assets/frames/`，风景画面落 `digest/assets/scenery/`。`video.md` 风景附录登记文件、时间点、地点及其对应依据、景色描述、已知季节或时段，不登记全部视频帧。风景画面不计入信息帧上限，数量按独立展示价值控制。

只有可用景色时保留景色概括与附录；信息和风景均无有效内容时允许简短说明。采集或读取失败与无有效内容分别记录。

## 5. 素材复用

图文配图优先按 `image.md` 全部图片附录选择，描述不足时查看已有低清拼图。视频信息素材按关键帧说明选择，风景照按风景画面附录选择。只引用已存档结果，不重新精读原图、视频或重跑管线。

报告素材在满足调用方要求的前提下最小化数量；原图引用 `images/`，视频素材引用 `frames/` 或 `scenery/`。调用方输出 Markdown 时复制素材到其输出目录并内联展示，不移动原件。

## 6. 实现与依赖

入口为 `skills/xhs-digest/SKILL.md`，图文和视频步骤分别在 `image-pipeline.md`、`video-pipeline.md`；输出按对应 `format-*.md` 模板生成。

脚本只做机械处理：`sheet.py` 拼图，`probe.py` 探测，`frame_grab.py` 抽帧，`setup-asr.sh` 检查或安装本地 ASR。阅读、定位、筛选与提炼由模型完成，不用 OCR 纯文本代替图像理解。

依赖为 Python/Pillow、ffmpeg/ffprobe、本地 SenseVoice 与 VAD 模型。二进制与模型由安装脚本准备，不入仓库；安装失败说明缺口并停止，不自行切换云端转写。字幕默认每 3 秒采样，信息过小或漏句时按依据核对，不默认增加全片采样密度。

## 7. 全局索引与"本地优先"（与 xhs-search 的衔接）— **暂不实现**

> 索引登记**当前不实现**。本节保留为后续设计：需要时从 `digest/note.md` 回填，不重新理解。

digest 完成时在 `<root>/xhs.db` 的 **digests 表**登记/更新一行（与 downloader 的 notes 表同库，各司其职）。

```sql
CREATE TABLE digests (
    note_id      TEXT PRIMARY KEY,
    title        TEXT,
    summary      TEXT,        -- 一两句话：这篇讲了什么、覆盖什么（= note.md 一句话总结）
    tags         TEXT,        -- 检索标签：信息类型，逗号分隔（= note.md 内容标签）
    form         TEXT,        -- 图文·N张 ｜ 视频·时长·形态
    published_at TEXT,        -- 发布时间（时效判断用）
    note_dir     TEXT,
    digest_dir   TEXT,
    digested_at  TEXT
);
```

- **检索用的字段**：title / summary / tags / published_at / form——检索方凭这五个字段判断这篇笔记值不值得打开；note_dir / digest_dir / digested_at 是定位与账本；
- 全部字段从刚写完的 `digest/*.md` 里抄，不重新理解；
- 表只是**检索索引**：内容的权威版本在 `digest/` 文件里，不一致时以盘为准，扫各笔记目录的 `digest/note.md` 即可重建。
