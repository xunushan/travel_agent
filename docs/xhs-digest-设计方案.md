# xhs-digest 设计方案

> **定位**：给一篇已下载的笔记，产出**解析存档 `digest/`**（文件夹）——**图片和视频的重要内容被定位、理解、整理一次，永不重做**；文本（正文/评论）只做轻提炼，重读便宜、下次按需再读。
> 若调用时给了"问题与要求"，再额外产出一份**报告**（与问题相关的总结＋关键素材）；**问题可缺省，缺省则只存档、不出报告**。
> 被 xhs-search 调用；自己不做搜索、不做下载。"先查本地已解析笔记、不够再搜小红书"是 xhs-search 的行为，见 §5。

---

## 1. 接口

|  | 内容 |
| --- | --- |
| **输入** | ① 笔记目录（`notes/<note_id>_<title>/`）；② 问题与要求（**可缺省**——缺省时只生成存档，不生成报告） |
| **输出** | ① **存档 `digest/` 文件夹**（笔记级，结构见 §2）；② **报告**（问题级，结构见 §3，仅当给了问题）＋关键素材路径清单 |
| **不做** | 搜索、下载（xhs-downloader）；跨笔记汇总、本地检索与取舍、闭合判断（xhs-search） |
| **暂不实现** | 向 `xhs.db` 的 digests 表登记（§5 保留为后续设计）。存档的权威版本在盘上，需要索引时扫 `digest/note.md` 可重建 |

---

## 2. 存档：一个文件夹，四个文件 + 两类产物

尺度原则：**只有图片/视频的理解必须存档**（重做贵）；文本提炼从简——够支持检索和快速判断相关性就行，细节下次重读原文。

```javascript
notes/<note_id>_<title>/
  digest/
    note.md       # 笔记提炼（轻）
    comment.md    # 评论提炼
    image.md      # 图片提炼（仅图文笔记）
    video.md      # 视频提炼（仅视频笔记）
    assets/       # 长期保留的产物
      asr-raw.txt         # ASR 原始转写（底账，不改动）
      asr-corrections.md  # ASR 校正记录（一次性校对账，不进 video.md）
      transcript.md       # 校正后文稿（视频的可读全文）
      frames/             # 视频关键帧
    scratch/      # 管线中间产物，删掉可重跑
      contact-*.jpg       # 拼图
      probe-*.jpg         # 探测帧
      sheet_*.jpg         # 字幕带长图
  images/         # 图卡与美照留在原地，image.md 引用原路径，不复制
  videos/         # 下载器落下的视频原件
```

**落点判据**：机械变换出来的（拼图、探测帧、字幕带长图、临时裁剪放大图）→ `scratch/`；经理解加工、会被长期引用的（原始转写、校正记录、校正后文稿、关键帧）→ `assets/`。**笔记根目录不留任何自己产出的文件。**

**盘面为准：`digest/` 目录在 = 解析过。**

### 2.1 note.md（轻）

```text
# 笔记提炼：<标题>
[头部信息栏：noteId / 作者 / 发布时间 / 互动 / 原链接 / 解析时间]

一句话总结：一句——主旨是什么 + 提供了什么信息
关键信息：按维度分条（路线 / 时间与时段 / 价格 / 交通与换乘 / 穿搭 / 天气……）
内容标签：逗号分隔，见下
```

- 头部信息栏**只留"这篇是什么"**：不写形态、所用管线、采集完整度，也不写采集异常（见 §2.6）；原链接剥掉 `xsec_token`；
- 关键信息**从旅游用户想知道的方方面面**总结，不是"骨架级正文要点"；
- **这份最后写**：图文笔记综合正文＋`image.md`，视频笔记综合正文＋`video.md`——只从正文提炼的 note.md 是残的；
- **一句话总结**：综合标题＋正文＋图/视频里读出来的内容；不写素材形态（"配一张导览图""视频里讲了""图卡""表格"），不写内部术语，不写评价；
- **内容标签回答"这篇能解决我哪一类问题"——写信息类型，不写信息本身**。粒度：比"九寨沟""秋季""一日游"这类泛词具体，又比"观光车 90 元不限次""进沟时间 9 点半前"这类单条结论概括。例如 `游玩路线 / 乘车换乘 / 徒步路段 / 打卡点 / 最佳时段 / 最佳机位 / 拍照穿搭 / 窗口期`，5–8 条。

### 2.2 comment.md

```text
# 评论提炼

## 补充事实
- <客观事实> —— 评论·<作者>（或"评论"）；多人佐证的注明

## 争议点
- <争议点> ｜ 说法：… ｜ 质疑：… ｜ 作者是否回应：… ｜ 倾向结论：…
```

- **只收客观事实**（规则、价格、开放与停运、运营方式、位置、时长），一条一事，按主题分行（票务 / 交通与运营 / 景点 / 安全）；主观偏好、他人游记式佐证、情绪、没有结论的碎片一律不收；
- 争议点**只写会改变取用决定的分歧**，四要素写全，每条 3–5 行，不铺陈过程；
- **过滤平台 AI 摘要**（`@点点` 这类）；
- **不写"阅读范围"节**。

### 2.3 image.md（重）

```text
# 图片提炼

## 信息图卡
### images/<文件名>
1. 一句话概括：<这是什么图 + 它提供什么信息>
2. 关键内容：分 2–4 个方面（方面名从主旨来，如 路线 / 上下车 / 徒步提示 / 打卡点）
3. 存疑：<图上没交代、自相矛盾、与正文冲突处；没有则不写>

## 附录：全部图片
| 文件 | 类型 | 内容 |
```

- **信息图卡全部精读、内容全提取**（无论正文提不提）；**记录照片一律不精读**，不进正文；
- **逐张判型必须写全**，登记在**最末尾的附录**里，不占正文位置；附录**只登记读者能用的信息**——不写拼图路径、角标、判型规则；
- **逐项属性写成「名称＝值」竖着列**，不照搬图上版式把项目名和值拆成两列逼读者数第几个；
- **存疑与关键内容同级**，一句一条；
- 引用 `images/` 原路径，不复制图片。

### 2.4 video.md（重）

```text
# 视频提炼：<标题>
[头部信息栏：note.md 那张表 + 时长·分辨率·帧率 / 形态 / ASR]

一句话概括

## 关键帧
### digest/assets/frames/<文件>（约 <秒> s）· <这一帧是什么>
1. 一句话概括
2. 关键内容

## 口播要点        # 按信息类型分行，每条注明来自字幕还是口播

## 矛盾与异常      # 每条：矛盾内容 + 证据链
```

- 头部信息栏的"形态""ASR"**不写原始转写与抽帧的存放路径**——那是内部账；
- **ASR 校正记录不在这份里**，单独放 `digest/assets/asr-corrections.md`（错误写法 → 正确写法 + 依据）。

### 2.5 assets/（长期保留）

- `asr-raw.txt`：ASR 原始转写（带时间戳，不改动）；
- `asr-corrections.md`：回画面校正的记录（地名同音错误必记，下次遇到同一批地名不用再校一遍）；
- `transcript.md`：校正后的完整文稿（视频笔记的"可读全文"）；
- `frames/`：视频关键帧。

中间产物（拼图、探测帧、字幕带长图、临时裁剪）一律落 `scratch/`，删掉可重跑。

### 2.6 数据质量（窄口径，归各文件自记）

只收两类：**存疑**（图上没交代、自相矛盾、与正文冲突——写 `image.md` / `video.md`，一句一条）、**内容矛盾**（图卡与口播、字幕与画面不一致——写 `video.md`，标注以哪个为准）。

**采集异常不进 `note.md`**：影响取用的（视频没声音、某张图打不开、评论没抓全）写进报告 §3；缺省无问题时即不落纸。判据：这条会不会改变后续使用者对某条结论的信任？不会 → 不写。信息不全不记（文本维度没挖是常态，下次按问题再读原文）。

## 3. 报告结构（问题级，固定三节；仅当给了问题）

```text
# 笔记整理报告：<标题>
[一行溯源：noteId / digest 路径 / 存档本次新生成还是复用 / 整理目的=当前问题]

## 1. 与问题相关的总结   ← 按问题维度分小段写全结论本体；只读本节应能回答本次问题；
                           结论标注来源（正文/图卡/帧/评论）
## 2. 关键素材           ← 与本问题相关的图卡/关键帧/美照：本地路径 + 一句话
                           （图卡引 images/ 原路径；关键帧引 digest/assets/frames/）
## 3. 缺口与待确认       ← 只列会改变决策、要再拿信息去确认的；按重要性排列
```

**约定**（防随意发挥）：

1. **报告只对当前这一篇负责**——不与其他笔记做对比、不做交叉引用（不写"另一篇的价值在…"）。跨笔记的汇总与取舍是 xhs-search 的职责；
2. 报告 §1 写全不写略——判据是"读者只读 §1 就能回答本次问题"；
3. 图卡/关键帧的内容**全提取、不省略**——存档的价值全在这；
4. 数据质量窄口径（§2.6），不往存档里塞噪音；所有"觉得不对、需要再确认"的点一律进 §3，不另开"可信度与存疑"节；
5. 不写建议搜索词——构造关键词是 xhs-search 的职责；
6. 不读的素材必须登记（image.md 逐张判型表天然覆盖）；
7. **增补只增不改**：补读产出一律增补进对应文件并注明增补日期与触发问题；发现旧内容错误才改，改时保留原说法与更正理由。

**§3 的写法**：先过筛子——这条缺口**会不会改变本次决策**？要再拿什么信息才能确认？答不上来的不列，宁少勿滥。按重要性排列，每条三项：

| 缺口内容 | 缺口类型 | 相关证据 |
| --- | --- | --- |
| <缺什么、要拿什么信息去确认> | 数据缺失／单一来源／口径不一／前提未证实／时效不匹配 | <档案里的出处：哪一帧 / 哪句口播 / 哪条评论> |

**问题线索指导提炼，但不划死范围**：给了问题时，问题里的关键词（目的地、季节、天数、要点的类型）是该重点挖、重点写的方位；与问题无关但读者确实用得上的信息照样提炼（存档是笔记级的，问题会变）。

## 4. 读法管线（存档生成用）

两条管线同一个思想：**先花很小的代价把"哪里可能有信息"定位出来，再花视觉 token。**

### 4.1 图文管线（四步）→ image.md + note.md

```javascript
① 正文先行      只读 note.json 正文（先别碰同目录其它文件）；这一步定出主旨；
                产出正文要点（note.md）+ 每张图的初判（"拍了X"=照片 ｜ "图上标了…"=图卡 ｜ 没提=交给探查）
② 拼图探查      scripts/sheet.py 全部图拼成低清总览（480px/格、角标编号、
                单张 ≤2400×1600、图多拆几张，存 digest/scratch/contact-*.jpg），
                多模态模型看一遍：逐张判型 + 每张一句话大致内容（写进 image.md 附录）
③ 定点原图      只精读判出的信息图卡（多模态模型读，不用 OCR 文本代替），
                按主旨分方面组织，解读写 image.md（引用 images/ 原路径，不复制）
④ 评论          按 §4.3 四类处置 → comment.md
```

**读图规则（按内容形态判型，具体可执行）**：

- 每张图二分——**信息图卡**：地图/导览图/路线图/行程单/票价表/时刻表/清单/带文字批注的示意图/汇总截图；**记录照片**：风景/人像/食宿环境照。判型在第②步完成（低清下一眼可辨）；
- **信息图卡全部精读**，无论正文提不提——全篇最有价值的图卡正文可能只字未提；
- **记录照片一律不精读**，用途只剩拼图选片与反向印证季节/场景——没有例外；
- 正文已用文字说完的点名图，第①步就否决；**值得读也完全不依赖正文点名**。

实测量级：19 张逐张读 ≈38k token，拼图＋1 张定点原图 ≈6.7k（省 82%）。`downloads.json` 不进上下文；`background-image` 重复图由 downloader 过滤，digest 不去重。

### 4.2 视频管线（五步）→ video.md + note.md

```javascript
① ASR 转写       依赖自检／安装：bash scripts/setup-asr.sh（缺则从源码编译＋下载模型）
                 FunASR SenseVoiceSmall（llama.cpp 二进制，VAD 时间戳）
                 → 原始转写存 digest/assets/asr-raw.txt
② 形态判别       scripts/probe.py 抽 ~11 帧：口播/动画？字幕带？图卡？——形态决定方法；
                 探测帧只用来判形态，不用来找图卡
③ 字幕带拼接抽样 ffmpeg 裁底部字幕带（182 token/帧），每 3s×12 帧
                 拼长图（450s → 13 张 ≈26k token）；漏句按 ASR 时间戳单帧回捞；
                 校正后全文写 digest/assets/transcript.md，
                 逐条校正依据写 digest/assets/asr-corrections.md
④ 图卡定点密抽   ASR 元话语定位（"汇总一下/截图保存/这张图/我标出来了"）→ 命中点
                 向后 60s 窗口 2-3s 密抽 → 帧落 digest/assets/frames/
⑤ 评论           按 §4.3 四类处置 → comment.md
```

**关键帧数量限制（硬规则）**：全片关键帧 **≤10 帧**；**只保留信息最全、无遮挡的那一帧**——同一张图的后续批注层**不单独留帧**，新增内容并进底图那一帧；口播里已讲过的更不单独留帧。帧多了说明定位没做准，回去收窄窗口。

**精看规则**：逐帧精看的只有**图卡帧**——作者把信息贴在画面上的位置（汇总表、路线图、价格表、行程单）。其余时间轴由字幕带拼接和 ASR 文本覆盖，**不逐帧看画面**；无字幕带的视频只在 ASR 报数字/名单/时间的信息节点抽帧核对。

**可信度分层**：**作者图卡 > 作者字幕 > 口播 > ASR 转写 > 评论区 AI 摘要。** ASR 对地名几乎必错（同音字，同一地名可能三种拼法），不能靠词频选写法，必须回画面校正——记录写 `digest/assets/asr-corrections.md`。作者图卡也可能有笔误（实测有把"米"标成"KM"的整列单位错误），用它的数字前先核量级。

### 4.3 评论的使用（两条管线共用）

**评论的角色 = 正文的补充与校正，不是独立信息源。** 按四类处置：

| 评论类型 | 处置 | 落到哪 |
| --- | --- | --- |
| 作者的回复/置顶（价格、规则、时间的追加说明） | 一手信息，可信度≈正文 | comment.md 补充事实，标"评论·作者" |
| 含具体信息的评论（价格、开放时间、实操细节） | 采纳，多人佐证优先 | comment.md 补充事实，标"评论" |
| 对正文说法的质疑/纠正 | 有回应→以回应为准；**未获回应→标"有争议"** | comment.md 争议点；与当前问题相关的同时进报告缺口 |
| 纯情绪/夸赞/无关；平台 AI 摘要 | 略过 | — |

两条纪律：**读序固定在精读之后**（先看评论会带着别人的注意力读正文）；**范围默认前 N 屏＋高赞**，不全滚。

## 5. 全局索引与"本地优先"（与 xhs-search 的衔接）— **暂不实现**

> 索引登记**当前不实现**（§1）。本节保留为后续设计：需要时从 `digest/note.md` 回填，不重新理解。

digest 完成时在 `<root>/xhs.db` 的 **digests 表**登记/更新一行（与 downloader 的 notes 表同库，各司其职）。

```sql
CREATE TABLE digests (
    note_id      TEXT PRIMARY KEY,
    title        TEXT,
    summary      TEXT,        -- 一两句话：这篇讲了什么、覆盖什么（= note.md 一句话总结）
    tags         TEXT,        -- 检索标签：信息类型，逗号分隔（= note.md 内容标签）
    form         TEXT,        -- 图文·N张 ｜ 视频·时长·形态
    published_at TEXT,        -- 发布时间（时效判断用）
    note_dir     TEXT,
    digest_dir   TEXT,
    digested_at  TEXT
);
```

- **检索用的字段**：title / summary / tags / published_at / form——检索方凭这五个字段判断这篇笔记值不值得打开；note_dir / digest_dir / digested_at 是定位与账本；
- 全部字段从刚写完的 `digest/*.md` 里抄，不重新理解；
- 表只是**检索索引**：内容的权威版本在 `digest/` 文件里，不一致时以盘为准，扫各笔记目录的 `digest/note.md` 即可重建。

```javascript
  bin/                      转写二进制（3.5 MB，gitignore，由 setup-asr.sh 编译）
    llama-funasr-sensevoice
  models/                   GGUF 模型（256 MB，gitignore，由 setup-asr.sh 下载）
    sensevoice-small-q8.gguf
    fsmn-vad.gguf

  命令行工具（环境依赖，不是本 skill 的代码）：
    ffmpeg                  字幕带裁剪＋拼接长图、一切抽帧的底层命令
```

**依赖自检**：跑视频管线前先 `bash scripts/setup-asr.sh`——查 ffmpeg/ffprobe/Pillow → 查 `bin/` 二进制（缺则从源码编译）→ 查 `models/`（缺则 `hf download`）。**ASR 缺失时不退回云端转写**，改为报告缺口并停止。`bin/` 与 `models/` 都进 `.gitignore`，不进仓库。

**SKILL.md 路由表**：

| 条件 | 去向 |
| --- | --- |
| 笔记目录已有 `digest/` 且给了问题 | 跳过管线 → 读 digest/*.md（文本细节按需重读原文）→ 生成报告 |
| 笔记目录已有 `digest/` 且未给问题 | 什么都不做（已存档） |
| note.json 类型 = 图文 | 图文管线（references/image-pipeline.md，调 sheet.py） |
| note.json 类型 = 视频 | 视频管线（references/video-pipeline.md，调 setup-asr.sh/probe.py/ffmpeg/frame_grab.py） |
| 存档不足以回答当前问题 | **定向补读**（图片/视频结论不够 → 补读对应素材，文本不够 → 重读原文）→ 按"增补只增不改"增补存档 → 再出报告；补读也不够 → 写进报告缺口 |

脚本只承担**机械变换**（拼图、抽帧、转写）；**所有阅读与判断由多模态模型完成**，不经过 OCR。

## 8. 成本纪律

- **图片/视频的理解永不重做**——这是存档存在的唯一理由；文本重读便宜，不追求一次结构化到位；
- 成本控制靠**管线内部分级**（拼图探查、字幕带粗扫＋按需回捞、定点精读），不是跳过图或视频；
- 量级参考：图文（19 张）≈ 11k；视频（450s 口播）≈ 26k＋图卡帧；复用出报告 ≈ digest 文本 ×2；
- 评论按 §4.3 四类处置、前 N 屏＋高赞，不全滚。
