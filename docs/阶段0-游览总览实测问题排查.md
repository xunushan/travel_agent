## 问题 1：「预期是一张大的路线图，不是信息轰炸」

> 原话：「首先我对这个环节的预期就是一张大的路线图，能涵盖所有的景点，给这么多图谁看，你想下你是要写一个海报告诉我这么游，不是信息轰炸」

**现象**：总览里 **34 张图**，其中景点美照 19 张、路线图/路书 15 张——没有一个"总览级"的路线主图在统摄全局。

**事实**：`grep -c '^!\[' 总览.md` = 34。图分布见 [`总览.md`](../../../Documents/travel_agent/overviews/gannan-jiuzhaigou-2026-10/总览.md)：`fig1`–`fig14` 是路线图/路书/实拍（散落在 §2 当季、§3 路线、§4 景点三节），`photo-*` 是每景点 2–3 张美照。

**根因**（设计层，不是执行走样）：

| 文件:行 | 原文 | 问题 |
|---|---|---|
| [设计方案 §5.1 第 3 点](tour-overview-设计方案.md#L89) | 「**优先**收录笔记现成高清线路图（注明来源）」 | 线路图是**偏好**不是**必备**；且限定"笔记里现成的"——没有就退化成文字。**没有"必须给出唯一一张总览主图"这条** |
| [设计方案 §5.1 第 4 点](tour-overview-设计方案.md#L90) | 「按路线分组，每景点 名称/一句话定位/**2-3 张美照**」 | 直接把"多图"写成了要求。8 个景点 × 2–3 张 = 16–24 张美照，**数量被结构决定了** |
| [overview-format.md:30](../skills/tour-overview/references/overview-format.md#L30) | 同上「**2-3 张美照**」 | skill 照抄了这条，**没有总量上限** |
| [overview-format.md:21-31](../skills/tour-overview/references/overview-format.md#L21-L31) | 五板块内容结构 | **没有"一页一主图""主图/辅图分级""全份图不超过 N 张"这类版式约束** |
| [overview-format.md:52-63](../skills/tour-overview/references/overview-format.md#L52-L63) | 生成要求与标准（交给 HTML/海报方） | 只约束了**渲染方式**（750px、模板填充、截图导出），**没有任何版面层级与信息密度标准** |

**结论**：「信息轰炸」不是执行跑偏，是**设计文档 §5.1 就是这么规定的**。skill 忠实实现了它。

**建议改法**（待定）：内容结构里把"总览主图"提升为**第 3 板块的必备首图**（须是一张能覆盖全部候选景点的路线图，笔记里没有就用文字结构图画一张）；美照从"每景点 2-3 张"改为"**每景点 0-1 张，且全份上限 N 张**"；§5.2 补版式层级标准（主图通版、其余缩略）。

**我实际设计的问题清单**（出自 [`总览.md:359-365`](../../../Documents/travel_agent/overviews/gannan-jiuzhaigou-2026-10/总览.md#L359-L365)）：

**根因**（规则层）：

| 文件:行 | 原文 | 问题 |
|---|---|---|
| [SKILL.md:58](../skills/tour-overview/SKILL.md#L58) | 「**意图已明确就直接开干**（如"10 月中旬去甘南"），**不为问而问**。只在缺下面这些关键项时问」 | 只给了**约束**（别乱问），没给**正向判据**（什么信号下**必须**问）。举的反例"10 月中旬去甘南"与本次输入几乎同形（目的地＋时间＋偏好），于是被判为"意图已明确" |
| [SKILL.md:60-65](../skills/tour-overview/SKILL.md#L60-L65) | 澄清触发表：主题范围模糊 / 出行时间 / 时间预算 / 显著偏好 | 四项**全是"缺失型"触发**。本次四项都不缺，所以全不命中——**漏掉了"输入本身有结构性特征时该问什么"** |
| [设计方案 §2.1](tour-overview-设计方案.md#L17) | 同上一句「意图已明确（如"10 月中旬去甘南"）→ 直接开干，不为问而问」 | 源头在设计方案。**这是设计层的缺口，skill 照抄** |
| [SKILL.md:37-38](../skills/tour-overview/SKILL.md#L37-L38) ＋ [question-design.md:36-42](../skills/tour-overview/references/question-design.md#L36-L42) | 「第 2 步 按用户已给的信息动态增减」「可选增题（默认不加，命中触发条件才加）」 | 增题的触发条件写在 question-design.md，**但主流程第 1 步（澄清）与第 2 步（设计问题）之间没有"拿输入去比对触发条件"这一动作**——第 0 步与第 1 步之间是断的 |

**这次真正该问而没问的**（按 question-design.md 自己的规则反推）：

1. **衔接段题（命中了增题条件却没加）**——[question-design.md:42](../skills/tour-overview/references/question-design.md#L42) 的触发条件是「行程**跨区域**、需要在两地之间串线时」，本次 **成都→甘南→九寨沟是三地两段**，明确命中。而且用户给的约束「**尽量不要往返重复路线**」本身就**是**一个衔接段问题。此事我已设计出 Q5，**却排在 Q1–Q4 之后，等被叫停也没轮到它**——最该先跑的题排到了最后。
2. **「不往返重复」这个约束没被翻译成判定口径**——它没有落进任何一个问题的"要求"里。按 [question-design.md:19](../skills/tour-overview/references/question-design.md#L19) 的杠杆「侧重」，它应当写进 Q1 的判定口径（"优先含闭环不折返的路线"）。
3. **题序没按用户约束排序**——用户的硬约束是"8 天内、不折返"，那么"哪些路线能塞进 8 天、怎么串"才是第一位的；我按标准模板从"有哪些路线"问起，把约束题推后。
4. **九寨沟侧没有设题**——总览自己也承认了：[`总览.md:384`](../../../Documents/travel_agent/overviews/gannan-jiuzhaigou-2026-10/总览.md#L384) G11「本轮没为九寨沟设题（题设计里它就是"落点"而非"目的地"）」。但用户明确说"10-20 晚上到九寨沟"，**九寨沟是行程终点而不是路过点**。

**建议改法**（待定）：澄清触发表加一栏**"输入已经说出口、但没被翻译成问题/口径的信号"**（跨区域、时间盒、显式约束、终点城市）；主流程加一步"**用输入逐条比对 question-design 的增题触发条件**"；并明确**约束类信号决定题序**——约束题排第一。

## 问题 3：「两个问题都没处理完，为什么有这么多笔记？」

> 原话：「你现在2个问题都没有处理完，为什么会有这么多篇的笔记，请给出用过的搜索词+筛选条件+top-k」

**事实**：24 篇下载量 ＝ Q1 的 8 ＋ Q2 的 16。搜索词/筛选/top-k 见 §〇 表。

**根因**：

| 文件:行 | 原文 | 问题 |
|---|---|---|
| [SKILL.md:74](../skills/xhs-search/SKILL.md#L74) ＋ [query-design.md:12](../skills/xhs-search/references/query-design.md#L12) | 「单题完整理解 ~10 篇软上限、20 篇硬停」「**top-k 默认 8**」 | **两者是相乘关系**：2 轮 × 8 = 16，而这是**每道题**的量。5 道题 × 2 轮 × 8 = 80 篇的**上限没有任何地方算过**。skill 里**没有"整趟调研的总预算"这一层**——每道题各自守自己的 10/20 篇，加起来无人管 |
| [SKILL.md:69-74](../skills/xhs-search/SKILL.md#L69-L74) | 停机准则表（三条） | **全部是"单题"口径**（闭合/轮次/深度上限）。调用方 tour-overview 逐题串行调用，**没有任何一层能看到累计成本** |
| [output-formats.md:92-105](../skills/xhs-search/references/output-formats.md#L92-L105) | run 日志 schema | **没有 `top-k` 字段**——`rounds[].candidates` 只记实际候选，事后无法区分"是 top-k 设成 8 还是搜出来就 8 条"。这次 Q1 恰好候选=8=top-k，**纯属巧合**，换个词就查不出来了 |
| [output-formats.md:88-90](../skills/xhs-search/references/output-formats.md#L88-L90) | 「每次运行落一份 JSON」 | **只在收敛时写**。Q2 没收敛 → 无日志 → 它的 16 篇下载**事后不可审计**（本次要靠 note 目录 mtime 反推） |
| [tour-overview SKILL.md:22-24](../skills/tour-overview/SKILL.md#L22-L24) | 「搜索词、筛选条件、top-k、读几篇**由它自己决定，不要干预**」 | 调用方**被明确禁止**过问成本，等于**没人能踩刹车** |

**建议改法**（待定）：run 日志 schema 加 `top-k` 与 `budget` 字段，并把日志改为**每轮追加**（不是收尾才写）；xhs-search 增加"**单次调用预算**"（如总下载 ≤ N 篇）；tour-overview 增加"**整趟调研总预算**"，且**开跑前把题数×成本报给用户**（此条已作为记忆 `long-pipeline-cost-control` 记录）。

## 问题 4：「粗筛没有起作用，箱包广告、别人晒自己的照片都下载下来了」

> 原话：「我发现粗筛没有起作用，很多无关的，有一个箱包广告的，别人赛自己照片的都全部下载下来了，没有包含和问题相关的信息量」

**事实**（两条硬证据）：

1. **Q1 的粗筛是 8/8 keep**——[`runs/0e65283a.json:19-26`](../../../Documents/travel_agent/runs/0e65283a.json#L19-L26) 八条候选全部 `"keep": 1`，**一个都没筛掉**。用户说的那些笔记在 Q2，而 Q2 的粗筛同样是从宽放行。
2. **但那 16 篇根本不是"粗筛判错"，是"粗筛管不着"**——按 [SKILL.md:50](../skills/xhs-search/SKILL.md#L50) 的主循环第 2 步，**下载发生在粗筛（第 3 步）之前**。下载量由 **top-k** 决定，与 keep 无关。Q2 的候选 16、keep 14 → **下载 16 篇**，正好证明这条。

**根因**：

| 文件:行 | 原文 | 问题 |
|---|---|---|
| [xhs-search SKILL.md:49-50](../skills/xhs-search/SKILL.md#L49-L50) | 「派子 agent 执行 discover＋download：…**下载 top-k 篇的 `note,cover` 两个内容件**」→ 下一步才是粗筛 | **顺序反了**。粗筛在结构上不可能减少下载量。这是用户"粗筛没起作用"的**直接原因** |
| [xhs-search 设计方案 §2 流程图:32](xhs-search-设计方案.md#L32) | 「派子 agent 执行 discover＋download top-k（内容件 note,cover）→ 返回候选清单」 | **设计文档就是这么定的**——不是执行走样 |
| [screening.md:19-20](../skills/xhs-search/references/screening.md#L19-L20) | 「只 drop 明显无关、**广告**、地区不符；拿不准一律 keep 并压低优先级——**误杀代价远大于白下载**」 | "广告"只有这一个名词，**没有任何可操作特征**：营销号、带货号、纯晒图、标题党怎么认？判者只能凭感觉，感觉偏松就全放行。而且"**误杀代价远大于白下载**"这句话**主动劝判者从宽**——在下载已经做完的前提下，这句话只放大了噪声 |
| [screening.md:11](../skills/xhs-search/references/screening.md#L11) | 输入只有：`noteId`、标题、200 字摘要、互动数、`publishedAt`、类型 | **没给主页信息**（是否带货号）、**没给图文比例**。像 `6ac721bb`《甘南自驾 哈佛猛龙4×24+2旅行袋｜自用存档》这种，标题里就有"旅行袋""自用存档"，**摘要不细看就漏过去了** |
| [query-design.md:25](../skills/xhs-search/references/query-design.md#L25) ＋ [:27](../skills/xhs-search/references/query-design.md#L27) | 天气类 → 「最新 / 一天内」；「以上均为建议默认值，可**灵活调整**（如条件太严导致候选稀少就**放宽**）」 | **只有放宽规则，没有收紧规则**。一放宽，"最新+一周内"就把穿搭、箱包、晒图号全拉进来了 |

**结论**：用户的三点观察**全部成立**，且**都不是执行失误**——"下载先于粗筛"是 [SKILL.md:50](../skills/xhs-search/SKILL.md#L50) 与设计方案 §2 白纸黑字写的。

**建议改法**（待定）：① 主循环改为 **discover → 粗筛（只看候选清单）→ 只下载 keep 的完整内容件**，去掉"下载 top-k 的 note,cover"这一步；② screening.md 补**可操作的广告/带货/晒图特征**（标题含商品词、"自用存档""链接在主页"、图文比 9:1 无文字等），并把"误杀代价远大于白下载"**限定在内容笔记上**（广告类不适用从宽）；③ query-design.md 补**收紧规则**（放宽后何时收、收多少）。

## 问题 5：「粗筛后的笔记为什么每篇都 digest 了」

> 原话：「另外粗筛后的笔记为什么没篇都digest了，设计的要求是不要全digest，截止到目前的笔记已经能充分回答问题了就不要再继续读了」

**事实**：Q1 `reads=8` ＝ `keep=8`（[`runs/0e65283a.json:30-38`](../../../Documents/travel_agent/runs/0e65283a.json#L30-L38)）——**粗筛输出多少篇，就 digest 了多少篇**，一篇没省。

**根因**：

| 文件:行 | 原文 | 问题 |
