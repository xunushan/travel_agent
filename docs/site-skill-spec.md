# 站点 Skill 规范

本仓库里每个站点一个 skill，放在 `skills/<站点>/`。这份文件规定**这个 skill 由哪些文件组成、
每个文件里必须有什么**。

浏览器那半边不在这里：站点 skill 只通过 `chrome-agent` 的命令面驱动它，怎么装、有哪些命令、
ref 怎么失效，都在 chrome-agent 那个仓库的 skill 里。这里只管站点自己的产出长什么样。

## 包结构

```text
<站点 skill 目录>/     # 独立项目空间；整个目录就是技能目录
  SKILL.md             # 入口：`description` 决定什么时候被选中；常驻内容 + 按需路由表
  references/          # 重内容：读完 SKILL.md 的路由表后，只读需要的那一份
  locators.yaml        # 页面语义规则（选择器、作用域、阈值）
  scripts/             # 确定性编排：CLI 调用、解析、去重、格式化、落盘
  schemas/             # 产出文件的结构合同，与脚本产出逐字段对应
  tests/               # 规则单测 + 产出与合同一致性
```

站点脚本在自己的目录树内互相引用，用绝对路径运行；**不要写死本机 skill 路径，也不要去探测
`chrome-agent` 的安装位置**——命令名就是接口，PATH 上的 `chrome-agent` 就是它。

## 渐进披露

技能目录整体会被加载，`SKILL.md` 是**唯一常驻进上下文**的文件，因此它的篇幅就是每次用到本
站点都要付的成本。规矩：

- **`SKILL.md` 宜 ≤200 行**，只放四样东西：`description`（决定何时被选中）、依赖与前置、
  「读什么」路由表、以及每次操作都不能违反的硬性不变量。流程给一条可粘贴的命令即可，
  逐步判据放 `references/`。
- **重内容一律下沉到 `references/*.md`**：完整流程、踩坑与证据、文件职责、领域判断要点。
  一份 reference 只讲一件事，**从 `SKILL.md` 一跳可达**（不再有第二跳，不再有嵌套目录）。
- **路由表必须写清"什么时候读它"**，不是"它里面有什么"。默认是**不读**——只有当下这一步
  真的需要时才读。

```markdown
# <网站>采集

## 按需加载
| 需要什么 | 读哪份 |
|---|---|
| 一步步跑完一次采集 | [references/flow.md](references/flow.md) |
| 报错了、行为反常 | [references/pitfalls.md](references/pitfalls.md) |
| 改脚本、改产出结构 | [references/files.md](references/files.md) |
```

写的是行为准则，不是日志：不写"这次改了什么"的变迁史，不写"验证用例"清单（回归测试在
`tests/` 里），也不重复同一事实三遍。
