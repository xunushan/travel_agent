# 游览路线总览（阶段 0）设计方案

> **定位：围绕用户的出行意图，提供候选景点列表与常见路线方案**——附当季情况（含近期天气）与时间预算，让用户有足够信息决定"去哪些景点、走哪条线"。
> 本 skill 有两处用户触点：**开始前澄清、产出后反馈循环**。调研执行逐题调 xhs-search（只传问题＋要求）；下载/理解细节见组件文档（xhs-search、xhs-digest、xhs-downloader）。

## 1. 接口

- **输入**：用户意图（目的地/主题 + 计划出行时间，其他信息通过澄清补齐）
- **输出**：《游览总览》HTML + 用户圈选后的景点清单（阶段 1 的输入）
- **做**：澄清意图 → 设计问题清单 → 逐题调 xhs-search → 汇总 → 组装内容 → 派子 agent 调生成 skill 出总览 → 反馈循环至圈选定稿
- **不做**：单景点的口碑、避雷、玩法细节（阶段 1）；实时路况/人流/天气的临行校准（阶段 3/5，本阶段只回答"这个季节通常怎么样 + 近期实况"）

## 2. 与用户的交互

### 2.1 开始前：澄清式提问（按需，非固定表单）

根据目标和用户已表达的意图，判断缺什么信息，有针对性地提澄清问题；意图已明确（如"10 月中旬去甘南"）→ 直接开干，不为问而问。只问影响调研方向和输出的关键项：

- 主题范围模糊（"想去川西" → 秋色？雪山？人文？）；
- 出行时间缺失（影响当季情况判断）；
- 时间预算缺失（影响路线方案筛选——3 天小环线还是 7 天大环线）；
- 显著偏好（"带狗""想露营"——用于调整判定标准，不展开约束）。

### 2.2 产出后：反馈处理（必需）

| 反馈类型 | 处理流程 |
|---|---|
| **圈选**（正常路径） | 记录每个景点的 待调研/排除 标记 → 输出阶段 1 任务清单 |
| **补充/纠偏**（"想看看 XX 方向""路线天数不对"） | 拆出新问题 → 再调 xhs-search → 更新总览对应章节 → 再次请用户确认 |
| **方向调整**（"其实更想看雪山"） | 回到 §2.1 澄清新方向，按需增补/替换问题后继续；已下载笔记留素材库可复用。**注意**：换目的地（"改去新疆"）不是反馈，是规划新行程，另走一遍完整流程 |

## 3. 问题设计（核心）

### 3.1 拆题原则

- 标准配置 **3 个问题**（是什么/怎么样/要多久）——是骨架不是定稿，必须根据用户提供的信息动态设计；
- "路线对比""景点卖点"不单独设题——笔记拿回来后在汇总环节内部完成；
- 口碑、避雷不进本阶段（阶段 1 的事）；
- 动态设计四杠杆：**题量**（意图已含的维度不重复设题）、**措辞**（主题语义写进问题，如秋色→问"秋色进度与峰值期"）、**侧重**（偏好改判定标准不改问题）、**增题**（命中触发条件才加，见 §3.3）。

### 3.2 标准问题清单

以"10 月中旬去甘南"为示例。**每个问题 = 一次 xhs-search 调用，只传两样：问题、要求**（要求＝输出结构＋判定口径；筛选条件由 xhs-search 自己决定）：

| # | 问题 | 要求（输出结构＋判定口径） |
|---|---|---|
| Q1 | 【目的地】有哪些常见的环线/路线方案？各包含哪些推荐景点、节点顺序和大致天数？ | 路线列表：名称/节点顺序/天数/一句话特点 + 景点清单（标注所属路线）。判定：正文要有路线结构信息（节点/天数/里程至少其一）；只有风景照的 drop |
| Q2 | 【出行时间】去【目的地】，景色、天气、路况怎么样？（含**近期天气实况**） | 当季看点与进度 / 气温穿衣 / 路况概况 / 近期天气实况，逐项标注信息年份与日期。判定：要有对应该时间段的描述；年份不明的 drop |
| Q3 | 走完【目的地】的这些路线一般需要多少时间？ | 各路线的建议天数 / 日均车程 / 节奏快慢。判定：要有明确时间/天数表述；泛泛而谈 drop |

### 3.3 可选增题（默认不加，命中触发条件才加）

| 候选问题 | 触发条件 |
|---|---|
| 从哪里进出【目的地】最方便？大交通/必经枢纽？ | 目的地偏远、入口多样（新疆、西藏等） |
| 【目的地】的海拔与高反概况？ | 高原主题（川西、甘南、西藏等），只问概况，细节归阶段 1 风险组 |

## 4. 主流程

```
1. 澄清（§2.1，按需）
2. 设计本次调研问题清单（§3，默认 3 题，动态调整）
3. 逐题调 xhs-search（只传 问题＋要求）
   → 返回：结论文档（含关键素材路径）+ 缺口声明（如有）
4. 汇总：交叉印证各题结论；合并去重景点（跨题的同点异称在此归并）；
   内部完成路线对比与景点卖点提炼；分歧如实并列；
   发现明显缺口 → 补一个问题再调 xhs-search
5. 组装输出内容：按 §5.1 内容结构整理各板块数据与素材路径
   （配图全部来自各题结论文档的关键素材路径，不另搜；
   路线图优先现成高清线路图/图卡帧，美照每景点 2-3 张）；
   板块料不足 → 补调 xhs-search，不硬凑
6. 派子 agent 调 html-poster skill：交内容＋要求＋标准（§5.2）
   → 拿回《游览总览》HTML（需要海报由同一 skill 导出）
7. 用户反馈循环（§2.2）；圈选完成 → 阶段 1 任务清单
```

汇总是本 skill 自己的核心重判断，主 agent 直接做——各题结论文档都是短文本，不派子 agent。

## 5. 输出契约

HTML/海报的**生成由独立的 html-poster skill 执行**（管线方案见《HTML海报生成方案调研.md》，同时承接本 skill 与阶段 1），本 skill 只负责两样：**交给生成方的内容结构**（§5.1）、**对生成结果的要求与标准**（§5.2）；执行时派子 agent 调生成 skill，交内容＋要求＋标准。

### 5.1 内容结构（交给生成方的数据）

《游览总览》自上而下五个板块：

1. **主题与一句话结论**：如"10 月中旬甘南秋色正盛，推荐 4-5 天小环线"；
2. **当季情况**：景色看点、天气（含近期实况）、路况概况（Q2，标注信息年份/日期）；
3. **常见路线方案**：每条路线 节点顺序/大致天数/一句话特点（Q1+Q3，汇总时内部对比）；优先收录笔记现成高清线路图（注明来源）；
4. **候选景点集合**：按路线分组，每景点 名称/一句话定位/2-3 张美照；
5. **笔记来源清单**：标题 + 链接 + noteId。

### 5.2 生成要求与标准（随内容一并交给生成子 agent）

- 单文件 HTML，移动竖版（宽 750px），板块顺序固定；
- 图片一律引用本地 `notes/` 路径（防盗链，不外链）；
- 模板填充模式：只把数据填进预置模板占位符，不自由发挥布局；
- 需要海报时由同一 skill 截图导出（deviceScaleFactor 2–3）；
- 版式质量标准与自检清单见《HTML海报生成方案调研.md》§五/§六/§七。

**前置纪律（本 skill 自查，不是生成方的职责）**：任何板块料不足，先补调 xhs-search，不允许把缺料交给生成方硬凑。

## 6. 完成标准

- 用户看完能回答：有哪些常见路线方案、各含哪些景点、这个季节（近期）去怎么样、走完需要多少天；
- 用户能看着美照圈选出进入阶段 1 的景点；
- 每个结论可溯源到 `notes/` 里的具体笔记。

**SKILL.md 示例**（带着可执行流程走，操作细节在 references）：

```markdown

| 要做什么       | 读哪份                          |
```
