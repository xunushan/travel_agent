# 游览总览设计方案

## 1. 定位与输入输出

围绕用户出行意向建立目的地全局认知，整理候选景点与常见参考线路，帮助判断有哪些看点、整体如何游览、大致需要多久、当季是否值得去，以及天气、路况和人流的影响。

- **输入**：用户的初步出行意向及已表达的相关条件。
- **输出**：《游览总览》Markdown，路线图与风景照在正文直接展示。
- **范围**：区域与整体线路层面的认知，不逐景点探查，不组织景点圈选，不确定具体路线或逐日行程。

## 2. 流程

```text
1. 生成调研大纲
2. 按大纲主题调研
3. 汇总判断
4. 判断缺口及是否补充
   需要补充 → 回步骤 2，再汇总判断
5. 输出游览总览
```

主 agent 生成大纲、汇总与判断缺口；每次唤起一个子 agent，使用 `xhs-search` 处理一个主题，传入问题与要求。要求包含期望信息与成功标准。各主题返回后检查后续内容是否已得到回答，避免重复调研。

## 3. 大纲生成

先依据用户意向明确地域范围与线路关系，再设计参考路线与景点问题；当季景色、天气、路况和人流按需要补充或合并，不固定题数。仅在无法形成有意义的问题时询问用户，不要求补齐目的地、时间或预算表单。

每个主题列明问题、期望信息与成功标准，开始调研前向用户展示。起终点、往返或区域衔接、大致天数等条件用于寻找接近的参考线路，说明符合之处与差异，不据此确定一条路线。

设计时考虑：

- 大范围目的地：了解主要区域、代表性线路、候选景点与组合关系。
- 进出或跨区域旅行：沿途线路与目的地内部游览均纳入研究，按需要合并或拆题。
- 已知走向或时间：寻找接近条件的已有参考线路，说明适用性。

以上为灵活设计的参考，不是固定意图分类。示例：新疆初识侧重主要游览方向与线路组合；成都往返西藏同时研究进出走向和内部游览；成都经甘南抵达九寨沟、约九天且不含九寨沟游览，则比较接近该条件的参考线路，不扩展到九寨沟内部。

## 4. 汇总与补充调研

整合各主题结论，去重点位，比较参考线路的覆盖范围、节点顺序、大致天数与节奏，并说明当季游览价值及风险。名称关系无法确认时保留原名；来源冲突并列说明。

先用已有结论补齐缺口。仍影响全局认知、线路比较或候选选择时，生成具体补充主题并重新调研；不影响本阶段判断的细节保留简要说明或留到后续。补充后仍无法解决的事项说明原因与影响，不反复发起相同调研。

## 5. 输出与素材

三个主体板块：

1. **参考路线**：有代表性的路线图或节点顺序，主要覆盖内容、大致时间及方案差异。
2. **当季景色概况与候选景点**：整体景观、看点与季节限制；按区域或线路整理候选景点及一句话特点。
3. **天气、路况与人流**：季节特点、近期情况、主要风险区域或路段，以及拥挤、住宿供给和价格压力。

末尾保留必要的缺口说明与实际引用来源，不生成 HTML、海报或圈选任务清单。

### 图片选择

- 参考路线图可以有多张，但有包含关系且无独立价值时保留较全面者；走向与覆盖范围近似时择优保留清晰、完整的一张；有实质方案差异时分别展示。
- 已调研笔记或视频明确提及某景点景色且有对应素材时，可展示 1–2 张代表性风景照；没有则省略，不额外搜索。
- 先复用主题报告素材，不足时按 `digest/image.md` 附录选片，描述不足才查看已有低清拼图。视频按 `digest/video.md` 风景画面附录选片，不重新精读或抽帧。
- 图片复制到总览 `assets/`，使用英文字母、数字和连字符命名，在 Markdown 中直接展示并注明来源。输出前检查文件与链接。

## 6. 保存与实现

```text
<ROOT>/overviews/<trip_id>/
├── 总览.md
└── assets/
```

与主题调研使用同一文件保存目录，不设默认值。`trip_id` 使用目的地或线路标识，出行年月明确时附加年月；同一次调研复用同一目录。

实现文件：

- `skills/tour-overview/SKILL.md`：技能定位、五步流程与纪律。
- `references/research-outline.md`：大纲生成、方向与示例。
- `references/overview-format.md`：Markdown 模板与填写要求。

## 7. 完成标准

用户能形成整体游览认知，比较参考线路，了解候选景点和当季价值，识别影响选择的风险与未知事项。结论可追溯，图片可直接查看；禁止替用户选定具体路线、编排逐日行程或为增加来源继续搜索。
