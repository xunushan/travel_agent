# 阶段 0 时效性筛选：实测结论

> 实测时间 2026-10-07，站点 xiaohongshu.com 网页版，登录态。
> 对照组关键词固定为 `甘南环线`（只改筛选，不改词），台账见 `~/Documents/travel_agent/xhs.db` 的 `runs` / `run_items`。

## 一、页面上真实存在的时效旋钮

| 维度 | 真实选项 | 备注 |
|---|---|---|
| 排序依据 | 综合 / 最新 / 最多点赞 / 最多收藏 / 最多评论 | 决定候选池的性质 |
| 发布时间 | **不限 / 一天内 / 一周内 / 半年内** | **没有「一月内」「三月内」** |
| 笔记类型 | 全部 / 图文 / 视频 / 用户 | 常驻行，不必开弹层 |
| 搜索范围 | 不限 / 已看过 / 未看过 / 已关注 | — |

「发布时间」只有 4 档这件事是硬约束：「近一两个月」这个最常用的窗口**只能靠不限时间 + 自己看笔记时间**来近似。

笔记页上有精确时间，可以逐条核对：`publishedAt`（首次发布）与 `updatedAt`（最后编辑）。
两者会不同：这次实测 `6a72c023` 发布 2026-08-05、编辑于 2026-08-14。**判断时效看两者较晚的那个。**

## 二、实测：时间筛选会精确地杀掉路线笔记

同一个关键词 `甘南环线`，只改筛选：

| 筛选 | 候选数 | 候选的实际形态 | 收藏量 |
|---|---|---|---|
| 排序依据=最多收藏，发布时间=不限 | 26 | 环线攻略、逐日路线、景点测评、支线机位 | 592–1914 |
| 排序依据=最新，发布时间=一周内 | 39（复跑 12） | 当日连载实况：「甘南环线第二站/第三站」「十一勇闯甘南小环线1/2」，时间戳为 3 分钟前 / 19 分钟前 / 1 小时前 / 16 小时前 | ≈0 |

这次实测筛出的 10 篇路线类笔记的发布时间分布在 **2025-06 ~ 2026-09**，最新的一篇也已是 **26 天前**：

```
2025-06-09  2025-08-10  2025-09-26  2025-10-18  2026-05-20
2026-06-25  2026-07-02  2026-07-25  2026-08-05  2026-09-11
```

**结论：一周内 → 路线类笔记 0 命中；性价比高的路线笔记普遍在 1–4 个月前。**
「最新 + 一周内」不是没用，它的产出是实况连载，回答的是另一类问题（路况/人流/天气）。

## 三、按问题类型分档（建议直接抄进阶段 0）

| 问题类型 | 时效性 | 建议筛选 | 判断依据 |
|---|---|---|---|
| 路线 / 环线结构、天数、住宿、门票 | **弱**（一年内基本不变） | `排序依据=最多收藏`，时间**不限** | 正文里的年份 + `updatedAt`；有数字（里程/门票/耗时）优先 |
| 景点取舍、口碑、避雷 | 弱–中 | 同上，**优先挑最近一次出行**（`updatedAt` 越近越好） | 景区规则会变（实测：甘加秘境 2026-08 起非景区住宿车辆禁入） |
| 路况 / 封路 / 施工 / 是否需预约 | **强**（周级） | `排序依据=最新;发布时间=一周内` | 要有明确日期或「今天/昨天」的表述 |
| 人流 / 排队 / 停车 | 强（周级） | 同上 | 节假日前后的实况最准 |
| 天气 / 气温 / 穿衣 | **很强**（天级） | `排序依据=最新;发布时间=一天内` | 只作临行校准，不进总结 |
| 最佳观赏时间 / 花期 / 秋色 | 中（同地每年差 1–2 周） | 关键词带月份（`甘南 10月中旬`）+ 时间不限；再用 `最新;一周内` 校准 | 往年同季笔记给「窗口」，当年实况给「落点」 |

## 四、两种取法：结构归阶段 0，实况归后续阶段

时效性不同的问题**属于不同的阶段**，不要在同一次搜索里混着取：

```bash
SITE=skills/xhs-downloader

# 阶段 0：取结构（路线、景点、门票、住宿）——不看时效，看内容完整度
python "$SITE/scripts/search.py" run --tab-id <tab> \
  --keywords "甘南环线" --filters "排序依据=最多收藏" --limit 20 --screen-limit 20

# 后续阶段（实况校验，如阶段 3）：取路况/人流/天气——只认最近的
python "$SITE/scripts/search.py" run --tab-id <tab> \
  --keywords "甘南环线" --filters "排序依据=最新;发布时间=一周内" --limit 20

# 判断：keep 记进台账 → 下载
python "$SITE/scripts/decide.py" keep --run-id <id> --note-id <ids> --reason "…"
python "$SITE/scripts/batch.py" --tab-id <tab> --run-id <id> --part body,media --dedup skip
```

两种产出**不能混在一张表里比较**：阶段 0 的候选收藏量高不代表它回答得了「现在路通不通」，
后续阶段的实况笔记收藏低也不代表它没用——它们回答的不是同一类问题。

## 五、边界与坑（这次实测实测）

1. **卡片上的时间在「最新」排序页读不可信**：30 张卡片全部报同一个矩形（x=267 y=217），整张表印的是同一张卡的时间。工具已改为检测到这种情况就印 `?`。**要精确时间就读笔记页的 `publishedAt`/`updatedAt`**（准的）。
2. **「半年内」是唯一可用的中期档**：想限定「近两三个月」只能 `不限` 之后自己看时间，不能靠筛选。
3. `updatedAt` 是判断「这条是不是最近改过」的唯一依据，**卡片上没有**——必须打开笔记才拿得到。
4. 时效弱的结论也要**记录笔记年份**：用 2025 年的路况去回答 2026 年的行程是错的，而站点的时间筛选帮不上这个忙。
