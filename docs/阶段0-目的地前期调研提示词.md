# 阶段 0：自驾游主题前期调研任务

## 任务目标与边界

**目标**：围绕调研主题【主题，如：川西的秋色】，基于小红书概括类笔记完成前期调研，产出一份《【主题】游览总览》——整体大路线图 + 推荐景点集合（每个景点附美照），帮助用户决定**去哪些景点**。

**边界**：

- 只搜**概括类笔记**（路线合集、主题盘点、环线攻略），**不搜具体单个景点**的深度笔记（如"稻城亚丁怎么玩"）；
- 不做门票、耗时、停车、季节适宜性等细节调研——那是下一阶段的任务；
- 不替用户做选择，只呈现路线、景点集合和口碑信号。

**完成标准**：

- 用户看完能回答：这个主题下有哪些值得去的景点、大家的大路线怎么走、什么时间去最合适；
- 用户能看着美照，直接圈选出进入下一阶段深度调研的景点。

## 工作方法

核心模式：**问问题 → 搜索 → 总结笔记**，一次搜索只解决一个问题。

### 第一步：拆问题

按"先整体、后局部；先有什么、后好不好"的顺序，把主题拆成有序的问题清单。参考问题（可按主题增删，但保持一次一题）：

- **Q1【路线层】**：这个主题下，大家常走的大路线/环线有哪些？各自的节点顺序和大致天数？
- **Q2【景点层】**：每条路线上被推荐的景点有哪些？（合并去重，标注景点所属路线）
- **Q3【口碑层】**：哪些景点被高频提及、评价高？有没有被集中吐槽、建议避雷的？
- **Q4【时效层】**：这个主题的最佳时间窗口是什么时候？（如秋色峰值期；对照用户出行时间判断是否赶得上）

拆题技巧：如果某题搜索结果太杂，就把它拆得更小（如 Q2 按路线逐条查）。

### 第二步：逐题执行

对每个问题，依次做四件事：

1. **搜索**：用 xhs_downloader 构造搜索词，可调整关键词与筛选条件（如按"最新"排序）。每轮搜索后对照当前问题盘点"已知/未知"，**基于未知的内容重新构造关键词再搜**，直到问题闭合或达到笔记上限；
2. **筛选**：广浏览相关笔记，但**每题以不超过 10 篇高质量笔记作为总结依据**（近期发布、点赞/收藏高者优先；经验上 5 篇左右高质量笔记通常就足以回答一个问题，不必凑满）；
3. **收藏**：阅读中发现对后续问题可能有用的笔记，先收藏，后面直接复用，不重复搜索；
4. **记录**：把该题答案记下来，再进入下一题。

### 第三步：汇总输出

1. **汇总**：交叉印证各题答案，形成结论（大路线结构、景点集合、口碑标注）；
2. **配图**：

- 整体路线图：**优先从已筛选/收藏的笔记中收录现成的高清线路图/海报**（如"川西环线线路图"这类），注明来源；没有合适的才自制文字版结构图；
- 景点美照：从已筛选/收藏的笔记中挑图，不另找图，每景点 2-3 张，记录来源笔记；

3. **生成**《【主题】游览总览》。

## 输出要求

《【主题】游览总览》一份。

- **格式**：统一输出 **HTML 页面**（适合浏览、可点击溯源链接）。后续再扩展"HTML → 竖版长图海报"的导出能力——两者技术上同源，长图即 HTML 的无头浏览器全页截图。不用 Markdown。产出的后续用途由用户决定，此处不做界定。
- **结构**（自上而下）：

1. **主题与一句话结论**：如"川西秋色，10 月中下旬为峰值，精华集中在 XX 环线"；
2. **整体大路线图**：优先收录笔记中现成的高清线路图（注明来源），辅以文字版节点顺序与大致天数；
3. **景点集合**：按路线/区域分组，每个景点给出——名称、一句话定位（如"雪山倒映的海子"）、口碑信号（高频推荐 / 有避雷争议）、2-3 张美照；
4. **笔记来源清单**：标题 + 链接，便于溯源。
