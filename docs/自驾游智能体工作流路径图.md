# 自驾游智能体工作流路径图（v3）

> 核心原则：**信息先行，决策后置**。人只在信息充分的节点做决策——阶段 0 末选定景点、阶段 2 末确认路线；约束条件（天数/人数/宠物等）在阶段 2 才介入，不作为起点。
>
> 编号规则：`阶段.任务`，可直接对智能体说"执行 1.2"逐项驱动。每个任务标注：输入 / 输出 / 完成标准。

## 总览流水线

```
0 目的地全局认知与候选清单 ──→【人：选定待调研景点】
1 单景点玩法细节调研
2 初步路线编排（此处才引入约束条件）──→【人：确认路线骨架】
3 行程细化（住宿/停车/吃饭/路况/打卡点）
4 预订与行前准备
5 监控与动态调整
6 旅途中记录
7 行后沉淀（数据回写 0/1，反哺下次出行）
8 系统辅助能力（贯穿全程）
```

---

## 阶段 0 ｜目的地全局认知与候选清单

**目标**：围绕用户意图（目的地/主题+出行时间），通过小红书**概括类笔记**提供**候选景点列表与常见路线方案**，附当季情况与时间预算，让用户有足够信息决定去哪些景点、走哪条线。**不深入任何具体景点**（口碑/避雷/玩法归阶段 1）。

**调研模式（阶段 0/1 通用）**：**一次一题**——把主题拆成有序问题清单，每题配好判定标准与筛选建议，派子 agent 调 xhs-search（一题多轮、粗筛排序、早停换词均由 xhs-search 编排）；每题支撑结论 ≤10 篇（一般 5 篇够）；逐题总结后汇总成结论；笔记复用原则：判断随问题走，内容随笔记走。

**执行工具**：三个组件——xhs-search（编排＋所有判断：粗筛排序/读循环/早停换词）、xhs-downloader（智能体驱动的下载工具：discover 搜索发现＋download 内容件下载、状态记账）、xhs-digest（单篇理解 → 笔记级解析存档＋问题级报告）。配套文档：《tour-overview-设计方案.md》（游览路线总览 skill）、《xhs-search-设计方案.md》。

| 编号 | 任务 | 说明 | 输出 |
|------|------|------|------|
| 0.1 | 澄清意图与拆题 | 按需向用户提澄清问题（主题范围/出行时间/时间预算等，意图明确就不问）；默认 3 个标准问题：Q1 路线与景点（常见环线方案、推荐景点、节点天数）→ Q2 当季情况（景色/天气/路况概况）→ Q3 时间预算（走完需要几天）；路线对比与景点卖点在汇总环节内部完成；按主题可选增题（大交通/高反概况） | 问题清单 |
| 0.2 | 逐题执行（调 xhs-search） | 先本地检索 digests 表（已解析笔记直接复用）→ 仍有缺口再走 discover＋download（搜索发现＋落 note/cover）→ 机器预杀 → 批量粗筛＋排序（J1）→ download 补齐 keep 的内容件（image/video/comment）→ 按优先级逐篇完整读（J2 三判断：增量/回答/keep-drop）；能完整回答就停（早停）；连续 3 篇无增量换词；单题 ~10 篇软上限、20 篇硬停 | 每篇结构化整理 + 缺口清单 + run 日志 |
| 0.3 | 汇总与内部对比 | 交叉印证各题答案；合并去重景点；内部完成路线对比与景点卖点提炼；分歧如实并列，不擅自调和 | 结论稿 |
| 0.4 | 生成游览总览（含配图） | 路线图优先收录笔记中现成高清线路图/海报，没有才自制文字版；美照从已筛笔记中挑，每景点 2-3 张 | 《主题游览总览》 |
| 0.5 | 【人工决策点+反馈处理】 | 圈选：待调研/排除；补充/纠偏 → 拆新问题重调 xhs-search 更新总览；意图变化 → 重新澄清 | 阶段 1 任务清单 |

- **输入**：调研主题（含季节语义，如"川西的秋色"）
- **输出**：
  - 给用户看：《主题游览总览》（统一 HTML 页面；后续扩展"HTML → 长图海报"导出能力）；结构为 一句话结论 → 当季情况 → 常见路线方案 → 候选景点集合（名称/一句话定位/美照）→ 笔记来源清单
  - 传递给阶段 1：用户圈选后的景点清单；所有 keep 笔记落盘 `notes/<noteId>/`（正文/图/视频/评论），作为后续阶段的素材库
- **完成标准**：人能回答——有哪些常见路线方案、各含哪些景点、这个季节去怎么样、走完需要几天；并能直接圈选待深度调研的景点

## 阶段 1 ｜单景点玩法细节调研

**目标**：对人选定的每个景点做深度拆解，产出可直接用于编排的「景点卡片」。

| 编号 | 任务 | 说明 |
|------|------|------|
| 1.1 | 景点数据结构定义 | 字段草案（基本信息/可达性/票务/玩法/后勤/风险/情报/调研状态），**由人定稿**，后续所有卡片按此填写 |
| 1.2 | 玩法线路组 | ① 游览线路图：拆清自驾段/景交段/徒步段（以九寨沟、毕棚沟为拆解模板）；② 精华子景点与最佳拍照时段；③ 时间窗安排（晨雾/日出/日落/日照金山）；④ 游览时长估算 |
| 1.3 | 后勤政策组 | 停车（收费、停车场→入口徒步距离）、景区内吃饭安排、宠物政策与携带方案、门票（预订渠道/价格/优惠政策及办理）、是否需两步路轨迹（高德无覆盖路段） |
| 1.4 | 风险注意组 | 野生动物、高反、落石、天气敏感度等注意事项 |

- **输入**：阶段 0.6 选定的景点清单
- **输出**：每个景点一张填好的卡片
- **完成标准**：每个景点的"怎么玩、玩多久、什么时间去、怎么去"全部有答案

## 阶段 2 ｜初步路线编排

**目标**：把选定景点串成路线骨架。约束条件在此阶段才引入。

| 编号 | 任务 | 说明 |
|------|------|------|
| 2.1 | 约束条件收集 | 出行天数、人数、是否带宠物、车型、预算、驾驶偏好（日里程上限等） |
| 2.2 | 参考路线比对 | 阶段 0 的成熟环线 vs 本次选定景点，确定主线走法 |
| 2.3 | 路线初排 | 高德地图验证：不绕路、日车程合理、景点时间匹配（衔接 1.2 的时长与时间窗） |
| 2.4 | 每日骨架 | 每天去哪几个点、住哪个城镇（粗略）、日里程 |
| 2.5 | 【人工决策点】 | 人确认路线骨架，可来回调整 |

- **输入**：阶段 0 全局认知、阶段 1 景点卡片、约束条件
- **输出**：逐日路线骨架 v1
- **完成标准**：人确认"就这么走"

---

## 阶段 3 ｜行程细化

**目标**：在已确认的骨架上填充可执行细节。

| 编号 | 任务 | 说明 |
|------|------|------|
| 3.1 | 每日行程卡 | 精确时间线、总距离、打卡点、精华玩法衔接、导航点、路况（标注非铺装段）、当日小结模板 |
| 3.2 | 住宿细化 | 每晚落脚点酒店筛选：停车、周边吃饭、宠物友好、价格 |
| 3.3 | 露营方案 | 免费露营地、是否需要床车露营 |
| 3.4 | 吃饭细化 | 路途中与景区内餐饮的具体安排（衔接 1.3） |
| 3.5 | 停车方案落实 | 逐点落实停车位置、收费、步行衔接（衔接 1.3） |
| 3.6 | 导航包 | 关键打卡点导航收藏 + 离线地图/两步路轨迹下载 |

**项目功能（待实现，已列入《需求迭代.md》）**：

1. **信息缺口追问**——某些细节（如观景台当日路况、露营地是否开放）多轮检索后仍无答案时，由智能体主动在小红书发布求助笔记，向近期到过的人发问；评论回收后补进当日行程卡。依赖「chrome-agent 发笔记」能力。
2. **两步路路线搜索推荐**——按路段/景点检索两步路轨迹并给出推荐，替代现在"人去两步路找轨迹、再回来下载"的手工环节（衔接 1.3 轨迹需求与 3.6 导航包）。

- **输入**：路线骨架 v1、阶段 1 景点卡片
- **输出**：逐日行程书（可执行版；形式上借鉴稻草人旅行的行程呈现，设计一套自有格式）

## 阶段 4 ｜预订与行前准备

| 编号 | 任务 | 说明 |
|------|------|------|
| 4.1 | 预订任务清单 | 酒店/门票/景交/索道，智能体出清单与提醒，人来下单 |

| 4.4 | 离线资源确认 | 离线地图、两步路轨迹下载完成 |

## 阶段 5 ｜监控与动态调整

| 编号 | 任务 | 说明 |
|------|------|------|
| 5.1 | 监控项注册 | 天气（雨雪/大雾/阴晴）、路况、突发事件、政策变化、景色情报（如川西秋色/红叶指数） |
| 5.2 | 频率与阈值 | 每项监控的查询频率与触发提醒的阈值 |
| 5.3 | 调整决策规则 | 原则：安全第一、保核心景点砍次要；每个关键节点预置 Plan B |
| 5.4 | 调整后回写 | 行程变更后同步更新行程书与导航包 |

## 阶段 6 ｜旅途中记录

| 编号 | 任务 | 说明 |
|------|------|------|
| 6.1 | 结构化体验记录 | 模板化字段：路况、游览时间点与光线（如"早上逆光应排下午"）、宠物策略、所思所想——供后续游客参考 |
| 6.2 | 账目记录 | 分类科目：油费/过路费/住宿/门票/餐饮/其他 |
| 6.3 | GPS 轨迹 | 低功耗、易操作的记录方案选型 |
| 6.4 | 照片归档 | 按日期×景点自动归集 |
| 6.5 | 每日小结 | 当天记录汇总，及时发现可调整项 |
